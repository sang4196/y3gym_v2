# Y3GYM 디자인 기준과 검토 결과 — A 방향

갱신일: 2026-10-10. **현재 프로젝트의 디자인 기준 문서**다. 밝고 정돈된 안내형 A 방향과 실제 화면 검토를 거쳐 확정한 공개 정보 구조를 기록한다. 최초 시안이나 과거 홈 배치를 현재 최종 기준으로 취급하지 않는다. 제품 범위·미결정 운영 정책은 [최신 PRD](../docs/PRD.md), 실행은 [프로토타입 README](README.md)를 따른다.

## 현재 구현과 승인 경계

사용자가 현재 공개 화면의 디자인 검토 종료를 확인했다. 기본 예시는 **본점·예시점 두 지점**이며 PC는 별도 창, 모바일은 같은 페이지 레이어 팝업이다. 관리자와 실제 서비스 연동까지 시각 승인한 것은 아니다.

| 범위 | 사용자 결정과 현재 상태 |
| --- | --- |
| A 방향·대표 화면 | ‘A. 밝고 정돈된 안내형’ 선택, ‘ok확인 진행’으로 1차 확인. 이후 ‘확인’으로 당시 홈 전체 확인 |
| 팝업 | 하단 여백 축소·텍스트형 ‘닫기 ×’·모바일 레이어로 수정 후 ‘팝업창은 일단 이정도면 될 것 같음’으로 확인 |
| 지점 탭 | ‘배치 합격’. 이후 홈/별도 지점 안내 분리와 지점·시설 통합을 요청하고 ‘ㅇㅋ 이대로 가자’로 확인 |
| 메뉴 | 트레이너 독립 메뉴 제거, 푸터는 지점 안내·소식만 제공하도록 요청. 현재 파일에 반영 |
| 소식 목록 | 밀도를 두 차례 줄인 뒤 ‘글 목록 통과’로 확인 |
| 시설 슬라이드 | 조작 버튼 없는 지점 안내 자동 슬라이드를 ‘시설슬라이드 통과’로 확인. 홈에 동일 적용 후 ‘ㅇㅋ 확인. 다음 진행하자’로 확인 |
| 소식 상세 | 요청한 하단 문의·목록 복귀 링크 제거를 반영. 상세 화면만의 별도 명시적 승인 기록은 없음 |
| 빈 데이터·실패 상태 | 정적 브라우저 검수·캡처 존재. 모든 상태별 캡처를 개별 시각 승인했다는 근거는 없음 |
| 관리자·실제 자료/지도·문의 | 소식·팝업·브랜드/홈·지점/시설 CMS는 별도 로컬 구현. 관리자 사용성 사용자 확인·실제 자료/지도·문의·운영 검토 전 |

자동 검사 통과는 디자인 승인이 아니다. 이전 캡처·JSON의 `USER_REVIEW_PENDING`, `HOME_REVIEW_PENDING` 등은 촬영 당시 상태이며 이후 사용자 확인은 이 문서에 따로 기록한다. 과거 파일을 승인 후 촬영물처럼 바꾸지 않는다.

실제 브랜드 자료가 없어 프로젝트명 텍스트 워드마크, 합성 시설·인물 사진, 예시 주소·운영시간·연락처를 사용하고 임시 자료임을 표시한다. 공식 로고·실제 지점·직원 사진이 아니며 문의는 실제 서비스로 연결하지 않는다. 자료 출처는 [이미지 기록](assets/images/GENERATED.md)과 [프로토타입 README](README.md#자료-출처)에 있다. 확인되지 않은 경력·자격·실적·가격·행사 혜택은 만들지 않는다.

Django/Wagtail과 전체 콘텐츠 초안·미리보기·공개 정책은 후속 사용자 ‘ㅇㅇ’로 선택했다. 이번 M1에서는 `backend/`에 소식 CMS를 구현하고 공개 목록·상세에 이 프로토타입의 CSS·글꼴을 그대로 연결했다. 승인된 시각 기준은 바꾸지 않았다. 새 [CMS 검수 자료](../backend/review/README.md)는 자동 검사 결과이며 관리자 사용성의 사용자 승인은 아직 없다. 기술 결정·다음 개발 단위는 [콘텐츠 관리·기술 설계](../docs/IMPLEMENTATION-PLAN.md)에서 관리한다.

**2026-10-10 후속 연결:** 글 작성/편집에 ‘팝업 설정’과 별도 적용을 추가하고 실제 DB·서버 시각·공개 리비전을 홈에 연결했다. 아래 최신 상태별 기준을 적용한다. 승인된 색상·타이포그래피·시설 슬라이드·팝업 닫기/하단 여백은 그대로 재사용한다. 정적 원본·기존 캡처는 보존하고 [새 관리자/실제 팝업 캡처](../backend/review/popups/README.md)를 분리했다. 이는 관리자 사용성의 사용자 승인을 뜻하지 않는다.

**2026-10-10 크기 수정:** 사용자가 실제 Whale의 복수 창 크기 불일치를 지적했다. CMS 팝업에 고정된 기준 폭·내용 높이 재측정과 화면 높이 채우기 제거를 적용했다. [별도 창의 실제 크기·캡처·검사 한계](../backend/review/popup-sizing/README.md)를 별도로 기록한다. 과거 headless 검수는 실제 창 크기의 완료 근거로 삼지 않는다. 이후 재노출·위치 보정과 사용자 ‘ok 다음으로 넘어가자’를 거쳐 후속 진행을 확인했다. Whale 직접 검사는 미실행이다.

**2026-10-10 M2-1 브랜드·홈 연결:** 승인된 홈 배치·색상·글꼴·사진 비율은 유지하고 소개와 브랜드 표시의 데이터 원본을 현재 공개 리비전으로 바꿨다. 편집 항목은 브랜드명·선택 로고·소개 제목/설명·선택 대표 사진/대체 설명/사진 중심이다. 로고가 없으면 텍스트 브랜드명, 대표 사진이 없으면 기존 `hero-layout--text-only` 배치를 사용한다. 공개본이 없으면 준비 중 문구와 지점·소식 탐색을 남긴다. 실제 소식/팝업에도 공개 브랜드를 사용하며 당시 정적 지점 화면은 미연결이었으며 아래 M2-2에서 실제 지점 안내를 추가했다.

새 로고 파일의 시작 표시 기준은 최대 180×32px의 비율 유지이며 실제 로고 교체 검토 전이다. 긴 텍스트 워드마크는 폭을 제한하고 말줄임하며 전체 이름을 접근성 설명에 남긴다. 제목·설명은 일반 텍스트로 출력한다. 미리보기는 관리자 권한을 확인하고 자동 팝업을 실행하지 않는다. [M2-1의 실제 홈/관리자 캡처·검수](../backend/review/brand-home/README.md)는 기존 정적 검수와 분리하며 관리자 사용성·공식 자료 교체의 사용자 승인으로 간주하지 않는다.

**2026-10-10 M2-2 지점·시설 연결:** `backend/`의 실제 홈·`/branches/`에 같은 지점 공개 리비전·시설 자식 목록을 연결했다. 기존 색상·Pretendard·간격·사진 비율·탭·자동 슬라이드 코드를 재사용하며 원본 HTML·스크립트·검수는 재생성하지 않는다. CMS 트레이너 0건으로 해당 영역을 숨기고 홈에 위치/트레이너 상세를 추가하지 않는다. 긴 CMS 지점명은 영역 안에서 줄바꿈하고 많은 탭의 현재 선택이 탭 줄 안에 보이도록 가로 위치만 보정한다.

공개 본점 우선·명시 선택 유지·미완성 초안/공개 필수값·마지막 철회 정책은 [PRD](../docs/PRD.md#fr-02-지점시설)를 따른다. 시설 0장과 빈 이미지 항목은 갤러리를 만들지 않고, 1장은 정적으로 표시한다. 선택 연락수단이 없으면 해당 문의 버튼을 숨기며 공개 지점 0곳이면 준비 중 안내와 브랜드/소식 탐색을 남긴다. JavaScript가 없으면 모든 공개 지점의 이름·주소·운영시간·기본 링크를 제공한다. [새 지점 캡처·자체 검수](../backend/review/branches/README.md)는 독립 검증·사용자 시각 승인·실제 기기 검증 완료와 구분한다.

**2026-10-10 M2-3 트레이너 연결:** 실제 지점 상세의 시설 다음·위치 이전에 현재 공개 프로필과 공개 소속 지점의 트레이너만 연결했다. 기존 카드·4:5 사진·PC/태블릿 2열·모바일 1열·색상/Pretendard/간격을 재사용하며 사진·직급·한줄 소개·약력이 없으면 해당 블록을 숨긴다. 약력은 분류 없는 단일 목록이다. 새로운 약력 카드의 사진/본문과 같은 행 카드의 시작 위치를 위로 맞추는 최소 CSS는 `backend/news/static/news/trainers.css`에만 두고 짧은 소개 카드의 기존 내부 정렬을 유지했다. 원본 프로토타입 HTML/CSS/자료·이전 캡처는 보존했다.

## 지점 통합 탭과 정보 구조

- 홈 순서는 브랜드 소개 → 지점 둘러보기(지점 탭·지점명·상세 진입·시설 사진 슬라이드) → 공통 최근 소식 → 푸터다. 별도의 시설 둘러보기 구역과 제목·표면 경계를 두지 않는다. 홈에는 트레이너·주소·운영시간·지도 상세를 표시하지 않는다.
- 홈의 시설 사진은 지점 안내와 동일한 자동 슬라이드로 표시한다. PC 3장·태블릿 2장·모바일 1장을 배치하고 조작 버튼은 표시하지 않는다. 4.5초마다 600ms 동안 한 칸씩 왼쪽으로 이동하며 끝에서 처음으로 이어진다. 모바일 스와이프와 사진 영역의 키보드 좌우 탐색, 세로 스크롤을 유지한다. 지점 변경 시 첫 사진으로 돌아간다. 사진 1장은 정적으로 표시하고, 0장이면 사진 영역을 만들지 않는다. JavaScript 실패 시 전체 사진 목록을 표시한다.
- 첫 소개 영역의 ‘시설 사진 보기’를 ‘지점 안내’로 바꾸고 선택 지점의 별도 안내 페이지로 연결한다.
- 상단 메뉴는 지점 안내·소식·문의하기로 구성한다. 홈과 지점 안내의 푸터 메뉴는 지점 안내·소식만 표시한다. 트레이너 독립 메뉴는 헤더와 푸터에서 제거한다. 지점 안내는 `branches.html`로 같은 탭에서 페이지 이동하며, 홈 내부 스크롤로 처리하지 않는다.
- 지점 안내 페이지는 현재 위치와 제목 → 지점 탭 → 선택 지점의 주소·운영시간 요약 → 시설 → 소속 트레이너 → 위치와 문의 → 푸터 순서다. 각 지점의 상세 구역을 한 패널 안에 묶고 선택한 지점만 노출한다.
- 기본 데이터는 본점과 예시점 두 개다. `branch-data.js`의 지점 목록에서 탭과 전체 패널을 함께 생성하며, 화면과 동작에 지점 수를 고정하지 않는다. 현재 정적 프로토타입에서는 데이터 추가 후 `npm run build:scenarios`로 반영한다. 이 정적 원본은 보존하며 실제 지점 등록·관리는 M2-2의 별도 백엔드에서 구현했다.
- 탭은 이름과 파란 밑줄로 선택 상태를 표시한다. 지점이 많으면 탭 줄 안에서 가로 스크롤하며 페이지 전체의 가로 넘침은 허용하지 않는다. 클릭, 좌우 화살표, Home/End, Enter/Space와 포커스 표시를 제공한다. 접근성 역할과 키보드 동작은 [W3C 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)을 참고한다.
- 지점 내부의 직접 링크를 우선하고, URL의 `branch`, 같은 탭에서 저장한 선택, 첫 지점 순서로 초기 패널을 정한다. 처음 방문했을 때는 첫 지점인 본점을 이름과 선택 표시로 명확히 보여준다. 삭제되었거나 알 수 없는 지점은 첫 지점으로 복구한다.
- 홈의 헤더·푸터 지점 안내와 지점별 자세히 보기는 별도 페이지로 연결하며 `branch`를 전달한다. 홈의 공통 전화·카카오톡 CTA와 모바일 문의 바는 선택 지점의 상세 문의로 연결한다. 지점 안내 페이지의 문의·트레이너 문의는 선택 지점의 내부 위치로 이동한다. 홈에 선택 지점을 표시하고 문의 영역에서도 지점명을 명확히 보여준다. 실제 문의를 임의로 본점에 연결하지 않는다.
- 소식 글과 PC·모바일 팝업을 거쳐 돌아올 때는 명시한 지점 선택을 URL로 유지한다. 탭 클릭으로는 페이지를 새로 불러오지 않는다.
- JavaScript가 없거나 앱 스크립트가 실패하면 탭 자리에 일반 지점 링크가 남고 모든 패널을 순서대로 노출한다. 주소·연락처·운영시간과 기본 탐색을 유지한다.
- 승인된 탭 배치는 [branch-tabs](review/branch-tabs/README.md)에 보존한다. 홈·지점 안내 분리 캡처는 [branch-pages](review/branch-pages/README.md)에 보존하며 현재 통합 지점·시설 슬라이드는 [branch-slides](review/branch-slides/README.md)에 기록한다. 기존 병렬 배치도 이력으로 보존한다.

## 공통 소식 목록과 상세

- 소식은 지점별 소유 없이 전체 지점 공통으로 표시한다. 기존 예시 제목·날짜·문구를 사용하고 실제 이벤트 혜택이나 운영 사실을 추가하지 않는다.
- 목록은 전체·공지·이벤트의 익숙한 밑줄 분류와 구분선 행으로 표시한다. 제목·분류·날짜·짧은 설명을 제공하며 사진이 없는 글에는 빈 사진 영역을 만들지 않는다.
- 사용자 추가 수정에 따라 행 위아래 여백은 PC 10px·모바일 8px, 모바일 행 내부 간격과 제목·설명 간격은 2px로 줄였다. 목록 제목은 PC 18px·모바일 16px, 짧은 설명은 14px·줄간격 1.45, 분류와 날짜는 13px다. 긴 제목과 설명은 생략하지 않고 줄바꿈한다.
- 분류는 기본 HTML 페이지 링크이며 현재 분류에 `aria-current`를 표시한다. 목록 기본 10건은 조정 가능한 초기값이다. 여러 페이지가 필요할 때만 번호 링크를 생성한다.
- 상세는 최대 800px의 본문 폭과 기존 글자 위계로 읽기 편하게 구성한다. 분류·제목·등록일·문단·강조·소제목·목록을 제공한다. 사용자 요청으로 본문 아래의 ‘지점 위치와 문의 보기’와 ‘목록으로 돌아가기’를 제거했다. 공통 메뉴와 현재 위치의 ‘소식’ 링크는 유지한다.
- 목록에서 상세로 이동할 때 분류와 페이지를 전달해 복귀한다. 선택 지점도 문의·홈·지점 안내까지 유지한다. 지정 지점이나 저장된 선택이 없으면 지점 선택으로 안내한다.
- JavaScript가 없어도 목록 분류·상세·메뉴가 남으며 기본 복귀 링크는 전체 목록으로 연결한다. 전체 목록이 비어도 분류와 안내·탐색을 제공한다.
- 정적 프로토타입은 `news-data.js`와 `templates/content.html`, `scripts/render-news.mjs`로 목록·상세를 생성한다. 이 정적 예시와 별도로 M1의 [서버 소식 템플릿](../backend/news/templates/news/list.html)은 실제 공개 리비전을 렌더링한다. 후속에서 팝업을 실제 DB·공개 홈과 연결했고 M2-4에서 홈 최근 소식도 같은 공개 리비전 조회에 연결했다. 정적 원본은 이력으로 보존한다.

## 지점 안내 시설 자동 슬라이드

- 사용자 확인을 받은 지점 안내의 자동 슬라이드를 홈에도 동일하게 적용한다. 공통 렌더링 함수와 `facility-gallery.js`·같은 CSS를 사용한다.
- 기존 사진 3:2·설명·PC 3장/태블릿 2장/모바일 1장 배치를 유지한다. 4.5초 대기 후 600ms 동안 한 칸씩 왼쪽으로 이동하며 끝에서 첫 사진으로 이어진다. 시간은 조정 가능한 초기값이다.
- 사용자 요청으로 일시정지·이전·다음 버튼을 제거했다. 모바일 가로 스와이프와 사진 영역의 키보드 좌우 탐색은 유지한다. 마우스가 영역에 있거나 키보드 초점이 내부에 있으면 자동 이동을 멈춘다. 화면 밖·비활성 탭·선택하지 않은 지점에서도 재생하지 않는다.
- 기기의 동작 줄이기 설정에서는 자동 재생을 끄고 전환 애니메이션 없이 수동 탐색을 제공한다. 지점을 바꾸면 선택 지점의 첫 사진으로 돌아간다.
- 0장/1장은 자동 슬라이드를 만들지 않는다. JavaScript가 없으면 기존 그리드와 전체 사진·설명을 노출한다. 연결용 사진 복제본은 보조기술과 키보드 탐색에서 제외한다.
- 모바일 팝업이 열리면 배경 슬라이드를 멈추고 닫힌 뒤 조건이 맞을 때 재개한다. 화면에 보이는 지점의 사진만 먼저 불러와 이동 중 빈 사진을 방지한다.
- [변경 검토와 캡처](review/facility-motion/index.html)에 기록한다. 지점 안내의 자동 슬라이드는 “시설슬라이드 통과”, 홈 적용 결과는 후속 “ㅇㅋ 확인. 다음 진행하자”로 확인받았다. PC·모바일 캡처와 실제 브라우저 영상을 보존한다.

## 배치와 반응형

- 최대 본문 폭은 1200px이다. 기본 좌우 여백은 32px, 태블릿 24px, 모바일 16px이다.
- PC는 소개·문의와 대표 사진을 좌우로 배치한다. 1024px 미만은 소개·사진·문의 순서로 쌓고 메뉴 버튼을 제공한다.
- 홈과 별도 지점 안내의 시설은 동일하게 PC 3장, 768–1023px 2장, 768px 미만 1장을 표시한다. 각 사진 아래에 제목과 설명을 배치하며 사진 비율과 간격을 공유한다.
- 트레이너는 PC·태블릿 2열, 모바일 1열이며 각 항목 안에서 사진과 소개를 나란히 배치한다. 최근 소식은 카드 대신 구분선이 있는 목록으로 표시한다.
- 위치 영역은 PC·태블릿에서 지도 배치 예시와 주소·문의 정보를 나란히, 모바일에서는 세로로 배치한다. 실제 지도는 연결하지 않는다. 소식 글 예시 한 개는 팝업의 연결 흐름 검수에 사용한다.
- 구역 간 기본 간격은 PC 80px, 모바일 48px이며 첫 소개는 사진과 첫 화면의 밀도에 맞춘 별도 내부 간격을 사용한다.
- 모바일 문의 바는 768px 미만에서 하단에 고정한다. 하단 안전 영역과 본문 여유 공간을 확보해 마지막 콘텐츠까지 스크롤할 수 있게 한다.
- 수치는 실제 CSS에 반영된 현재 기준이며 절대 고정값은 아니다. 추가 조정은 승인된 시각 방향과 영향을 확인하고 실제 화면으로 검토한다.

## 버튼, 링크, 기본 탐색

버튼은 높이 48px, 모서리 8px을 시작값으로 한다. 주요 버튼은 포인트 배경과 흰 글자, hover는 `#274C6B`이다. 보조 버튼은 흰 배경과 짙은 글자, 중립색 테두리이며 hover는 `#EEF2F6`이다. 본문 링크는 포인트색과 밑줄을 사용한다. 키보드 포커스는 2px 테두리와 3px 바깥 간격으로 표시한다.

지점 안내는 별도 HTML 페이지로 연결한다. 헤더·푸터의 소식과 홈의 소식 모두 보기는 별도 목록으로 이동한다. 지점 상세 안의 시설·트레이너 문의·위치와 문의는 내부 링크를 사용한다. 공통 문의는 선택 지점의 별도 페이지로 연결하고, 트레이너 문의와 위치·문의 구역은 해당 지점명을 표시한다. JavaScript가 없으면 모든 지점 패널·모바일 메뉴 목록·같은 탭의 소식 링크를 기본 노출해 핵심 본문과 탐색을 유지한다. 문의 버튼에는 실제 연락처나 외부 서비스 주소를 넣지 않는다.

## 검수 자료와 한계

PC 1440×900 첫 화면과 1440px 폭 전체, 모바일 375×812 첫 화면과 375px 폭 전체를 보존한다. 전체 캡처는 같은 폭의 긴 브라우저 뷰포트로 촬영해 고정 문의 바를 맨 아래에 표시했다. 실제 고정 바의 위치와 본문 가림은 375×812 뷰포트에서 별도로 검사한 기록이 있다.

글꼴·이미지 로딩, 가로 넘침, 기본 메뉴·링크, 하단 콘텐츠 가림을 정적 Chromium에서 검사했다. 실제 기기 검수와 운영 기능 전체의 회귀 검수는 완료하지 않았다. 이번 M1에서는 기존 자료를 재생성하지 않고 소식 CMS만 별도 검사·캡처했다. 관리자 편집 경험의 사용자 승인은 아직 받지 않았다.

사용자 시각 확인은 배경/흰 표면/포인트색의 밸런스, 사진 분위기·크기·잘림, 제목과 본문의 위계, 구역 여백과 첫 화면 밀도, 문의 버튼의 강조 수준과 익숙한 사용감을 기준으로 받았다.

## 상태별 구현 기준

- 768px 이상에서는 별도 창 팝업을 사용하고 글별 이름으로 창을 재사용한다. 768px 미만에서는 홈 안의 네이티브 dialog 레이어를 사용하며 새 창·탭을 만들지 않는다. **최신 사용자 결정으로 중첩 전체 자동 노출·글 등록 순서·전체 지점 공통**이다. 모바일은 한 개를 닫으면 다음 대상을 표시한다. **일반 닫기 후 새로고침·홈 재방문마다 다시 노출**하며 기존 탭당 한 번 제한은 폐기한다. 같은 화면에서 크기·지점 선택만 바꿀 때는 추가 자동 열기가 없다. [이번 동작 검증](../backend/review/popup-revisit/README.md).
- **평소 ‘알림 보기’ 버튼은 제거한다.** 자동 차단·로딩 실패 시에만 해당 글의 텍스트형 ‘직접 열기’ 링크를 제공한다. 새로고침에서 자동 시도를 다시 하고 실패하면 복구 링크를 남긴다. 세션 기록은 노출 제한에 사용하지 않는다. JavaScript 실패 시 같은 탭의 연결 공개 소식 글로 이동하는 HTML 링크를 제공한다. 정적 원본과 기존 캡처에 남은 ‘알림 보기’는 과거 구현이다.
- 모바일 레이어는 내용 높이에 맞추고 좌우 16px, 하단 내부 여백 12px을 시작값으로 한다. 짧은 화면에서는 본문만 내부 스크롤하고 오늘 숨김·닫기는 계속 보인다. 레이어가 열린 동안 배경 스크롤·탐색을 막고 하단 문의 바를 숨긴다. 닫기·바깥 영역·Escape로 닫으며 보던 홈 위치와 수동 진입 링크의 포커스를 복원한다. 소식 글은 같은 탭에서 연다. PC 크기로 전환되면 레이어를 닫고 스크롤 잠금을 해제한다.
- 팝업 하단은 ‘오늘 하루 보지 않기’와 같은 14px의 ‘닫기 ×’ 텍스트 컨트롤로 구성한다. 닫기의 배경·테두리는 없애고 44px 클릭 영역과 키보드 포커스를 유지한다. 하단 여백은 12px이다. **실제 CMS 별도 창은 본문 폭 480px·초기 높이 520px을 요청하고 글꼴·사진 준비 후 내용 높이로 맞춘다.** 창 생성 직후 임시 `outerWidth`를 목표 폭으로 사용하지 않으며 비동기 크기 변경 후 재측정한다. 화면보다 긴 내용은 창 크기를 작업 영역 이하로 제한하고 스크롤한다. 재시도는 짧은 초기 구간으로 제한해 이후 사용자 크기 변경을 방해하지 않는다. 새 탭/크기 변경 제한에서도 본문과 하단 조작줄을 붙여 배치해 큰 빈 공간을 만들지 않는다. 정적 원본의 초기 700px·화면 높이 채우기는 과거 구현으로 보존한다.
- **PC 위치 — 최신 사용자 요청 반영:** 중앙 주변을 3×3 구역으로 나눠 순서를 섞고 각 구역 안에서 위치를 무작위로 조정한다. 한 묶음의 첫 9개는 구역을 중복 선택하지 않으며 그 이후에는 다시 섞는다. 창 중심의 분산 폭은 화면 중앙에서 가로 최대 ±180px·세로 최대 ±100px을 시작값으로 하고 작업 영역의 12%·10%와 실제 남는 공간 중 작은 값으로 제한한다. 가장자리 여백은 기본 48px이며 매우 작은 화면에서는 최소 창 공간을 위해 줄인다. 시작 좌표는 홈의 작업 영역 원점·예상 창 테두리를 포함해 계산하고, 실제 크기가 정해진 뒤 같은 랜덤 기준점과 실제 열린 화면으로 다시 맞춘다. 큰 창은 안전 영역 안에서 스크롤하며 서로 일부 겹칠 수 있다. 초기 보정은 최대 12회·4.5초 이내로 제한하고 이후 사용자의 이동·크기 변경을 되돌리지 않는다. 이동 제한·새 탭 대체에서는 실제 좌표를 강제할 수 없다. 모바일 배치는 변경하지 않았다. [실제 창 좌표·캡처·제한](../backend/review/popup-position/README.md)을 구분한다. 후속 사용자 “ok 다음으로 넘어가자”로 다음 단계 진행을 확인했으며 실제 Whale 검증 완료를 뜻하지 않는다.
- 연결 글 공개, 활성 상태, 시작 시각 포함·종료 시각 제외를 서버 시각으로 확인한다. 모바일은 다음 레이어 직전에 다시 판정한다. 오늘 숨김은 팝업별 한국 시간 다음 날 0시까지 자동 노출을 숨기며 직접 URL은 서버 공개·기간 조건만 적용한다. 제목·설명·사진·연결 글은 현재 공개 리비전에서 가져온다.
- PC는 자식 창의 내용 준비 완료 메시지, 모바일은 레이어의 사진·글꼴 준비 완료 후 표시를 기록한다. 자동 차단·로딩 실패를 표시 완료로 간주하지 않으며 수동 재시도로 복구한다. 세션 저장소 사용 불가는 자동 열기를 막지 않는다. 오늘 숨김 저장이 실패하면 안내하고 체크를 해제하며, 다시 닫으면 일반 닫기로 처리한다. 일반 닫기는 숨김을 저장하지 않는다.
- 기본 홈·빈 데이터·실패 화면 모두 본점과 예시점의 두 지점을 사용한다. 홈의 공통 문의는 선택 지점의 상세 페이지로 연결한다. 상세 페이지에서는 한 패널 안의 시설·소속 트레이너·주소·운영시간·연락처를 함께 전환하고, 연결 소식에서 돌아올 때도 선택 지점을 유지한다. 예시점은 실제 등록 지점이 아니며 이름·주소·전화·사진 재사용을 모두 임시 자료로 표시한다.
- 선택 콘텐츠가 없으면 대표 사진·시설·트레이너 블록을 숨기며 가짜 콘텐츠를 채우지 않는다. 소식은 등록된 글이 없음을 안내한다.
- 사진 실패는 중립 배경과 설명으로 대체한다. 스크립트 실패 시에도 HTML 본문·주소·읽을 수 있는 연락처 예시·모바일 메뉴 목록·링크 탐색을 남긴다.
- 이 폴더의 원본 공개·기간 검수는 정적 가상 데이터의 브라우저 동작 범위다. 실제 서버 공개·기간·비공개 초안 보호는 `backend/`의 [별도 검수](../backend/review/popups/README.md)에서 확인한다. 실제 문의·지도·운영 배포는 미구현이다.

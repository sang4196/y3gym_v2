# Y3GYM UI 프로토타입

**2026-10-14 기존 잔여물 정리:** 사용자 승인으로 완료 서버7개, legacy DB31개, 임시 폴더63개와 과거 bulk 결과물을 정리했다. 현재8776·원본성8769·canonical8767과 제품/현행 도구·원본 데이터는 보호했다. 과거 자료 링크의 ‘정리됨’은 결과 변경이 아니며 [현재 검증·원실패·한계 요약](../backend/review/README.md)과 [실제 정리·보류](../backend/review/cleanup-residue-01/README.md)를 따른다. 좁은 독립 확인을 완료했으며 기존 경고·관측 한계는 유지한다.

A 방향의 홈 전체와 현재 PC·모바일 팝업을 사용자가 확인했습니다. 이후 지점 통합 탭도 “배치 합격”으로 확인받았습니다. 현재는 후속 요청에 따라 홈의 지점·시설 미리보기를 하나의 사진 슬라이드 구역으로 합치고 트레이너·위치·문의 상세를 별도 지점 안내 페이지로 옮겼습니다. 헤더와 푸터의 트레이너 독립 메뉴는 제거했습니다. 승인된 방향을 바탕으로 공통 소식 목록과 공지·이벤트 상세를 추가했으며 소식 목록은 “글 목록 통과”로 확인받았습니다. 기본은 본점·예시점 두 지점이며 선택한 지점의 정보만 표시합니다. 이 폴더는 정적 UI이며 관리자·백엔드는 `backend/`에서 별도로 구현합니다. 실제 지도와 문의 서비스는 미연결입니다.

사용자의 후속 결정에 따라 **기본 홈과 이후 예시는 본점·예시점 두 지점**입니다. **PC는 별도 창, 모바일(768px 미만)은 같은 페이지의 레이어 팝업**을 사용합니다. 닫기 스타일과 A 방향은 유지합니다.

## 실행

이 디렉터리에서 `npm start`를 실행한 뒤 <http://localhost:8767>을 엽니다. 런타임은 Python의 정적 파일 서버이며 프런트엔드 빌드나 앱 의존성이 필요하지 않습니다.

## 시각 검토

- PC: 1440×900 첫 화면, 1440px 폭의 전체 구현 범위.
- 모바일: 375×812 첫 화면, 375px 폭의 전체 구현 범위.
- 배경/흰 표면/포인트색, 사진 구도, 글자 위계, 여백, 문의 버튼을 확인합니다.
- 자동 검사는 사용자 디자인 승인을 대신하지 않습니다. 기존 홈·팝업·통합 지점 탭은 확인받았으며 홈·지점 안내와 통합 지점·시설 슬라이드도 “ㅇㅋ 이대로 가자”로 확인받았습니다.

사용자의 “글 목록 통과. 시설슬라이드 통과.”로 소식 목록과 버튼 없는 시설 자동 슬라이드를 확인받았습니다. 이어진 요청으로 메인화면에도 같은 자동 슬라이드를 적용했으며, 후속 “ㅇㅋ 확인. 다음 진행하자”로 홈 적용도 확인받았습니다. [콘텐츠 관리·기술 설계](../docs/IMPLEMENTATION-PLAN.md)의 두 추천안은 사용자 “ㅇㅇ”로 확정했습니다. 이후 M1에서 Django/Wagtail + PostgreSQL의 **소식 CMS를 `backend/`에 분리 구현**했습니다. 실제 실행법·검증·새 캡처는 [백엔드 README](../backend/README.md)와 [검수 기록](../backend/review/README.md)에 있습니다. 이 폴더의 UI 코드·가상 데이터·기존 캡처는 그대로 보존했습니다.

**2026-10-10 팝업 연결 후속:** 실제 CMS 글 편집의 ‘팝업 설정’과 DB·공개 홈을 `backend/`에서 연결했습니다. 중첩 전체 자동 노출·글 등록 순서·전 지점 공통이며 평소 ‘알림 보기’ 버튼은 제거하고 차단·실패 시 텍스트 복구 링크만 제공합니다. 모바일은 한 개씩 순차 표시합니다. 이 최신 정책은 [실제 홈](http://localhost:8768/)과 [새 검수 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 적용합니다. **원본의 단일 팝업·‘알림 보기’·브라우저 시각은 당시 참고 구현으로 보존**하며 재생성하지 않았습니다. 홈 전체 CMS화·관리자 사용성 승인은 아직 아닙니다. 이전 8767 홈을 실제 홈으로 연결하는 실행법은 [루트 README](../README.md#소식-cms-실행과-확인)에 있습니다.

프로젝트 전체의 현재 상태·제품 범위는 [루트 README](../README.md)와 [최신 PRD](../docs/PRD.md), 최종 디자인·승인 범위는 기존 [DESIGN.md](DESIGN.md)를 기준으로 합니다. `review/`의 이전 배치·당시 승인 대기 표시는 검수 이력이며 이후 결정과 구분합니다.

과거 1차 검수와 홈·통합 탭·페이지 분리·소식·상태 결과의 `review/home/`, `review/current-home/`, `review/branch-tabs/`, `review/branch-pages/`, `review/branch-slides/`, `review/news/`, `review/states/`는 정리된 당시 저장 위치입니다. 현재 이 폴더에는 `review/facility-motion/`의 대표 [PC 홈](review/facility-motion/home-desktop-full.png)·[모바일 홈](review/facility-motion/home-mobile-full.png) 두 캡처만 남겼습니다. 승인 내용·원실패·검증 범위는 [유지 요약](../backend/review/README.md)을 따릅니다. 아래 npm 검수 명령은 기존 스크립트 안내이며 이번 정리에서 실행/재검증하지 않았습니다.

과거 전체 캡처 폴더는 선별 정리됐고 현재 대표 캡처는 유지 요약에서 확인합니다. 아래 과거 보존/실행 설명은 당시 기록이며 현재 존재하는 결과물 전체를 뜻하지 않습니다. 남긴 캡처 열람에는 의존성 설치가 필요 없습니다. 브라우저 검수를 재실행할 때는 `npm ci`와 `npx playwright install chromium` 후 정적 서버가 실행 중인 상태에서 다음 명령을 사용합니다. 명령은 캡처·JSON을 덮어쓰며 `review:states/news/gallery`는 HTML도 재생성합니다. 이번 M1에서는 이 명령들을 실행하지 않았으며 기존 자료를 보존했습니다.

- `npm run review:states`: 정적 검수 화면을 재생성하고 팝업·두 지점·빈 데이터·실패 상태를 검사하며 캡처합니다.
- `npm run review:news`: 소식 목록·상세·빈 목록을 6개 화면 폭에서 확인하고 분류/목록 복귀/선택 지점/페이지 이동/JavaScript 대체 동작을 검수하며 캡처합니다.
- `npm run review:gallery`: 홈과 지점 안내의 공통 시설 자동 슬라이드, 정지·반복·지점 전환·모바일 스와이프·동작 줄이기·빈 사진/실패 상태를 확인하고 캡처합니다.
- `npm run build:scenarios`: 기본 홈과 검수용 HTML을 재생성합니다. 공통 마크업은 `templates/home.html`·`templates/branches.html`·`templates/content.html`, 소식 데이터와 렌더링은 `news-data.js`·`scripts/render-news.mjs`, 지점 목록은 `branch-data.js`, 탭·패널 렌더링은 `scripts/render-branches.mjs`에서 관리합니다. 생성된 `index.html`, `preview-*.html`, `branches*.html`, `news*.html`, `news/*.html`은 직접 수정하지 않습니다.
- `npm run review`: 홈과 지점 안내 페이지를 각각 6개 화면 폭에서 검수하고 PC·모바일 캡처를 수행합니다. 자동 팝업은 이 촬영에서만 억제하며 팝업 동작은 앞의 별도 명령으로 검사합니다.
- `node scripts/verify-states.mjs --popup-only`: 팝업 수정 후 관련 항목만 확인하며 `review/states/popup-refinement-checks.json`에 별도로 기록합니다.
- `node scripts/verify-states.mjs --branch-only`: 지점 탭·확장 데이터·연결 동선·빈 데이터·실패·JavaScript 대체 동작만 확인하고 `review/states/branch-slide-checks.json`에 기록합니다.

## 지점 탭과 추가 데이터

`branch-data.js`의 목록을 순회해 두 페이지의 탭과 패널을 함께 생성합니다. 홈은 지점명·상세 진입·시설 사진 슬라이드를 한 구역으로 표시하며 `branches.html`은 주소·운영시간·시설·트레이너·위치/문의 전체를 제공합니다. 목록에 지점 데이터를 추가하고 `npm run build:scenarios`를 실행하면 탭도 늘어납니다. 실제 지점 등록 API나 관리자 기능은 이번 범위에 없습니다. 기본 예시는 두 지점을 유지하고, 검수 안에서만 목록을 일곱 지점으로 확장해 수가 고정되지 않았는지 확인합니다.

모바일에서 많은 탭은 탭 줄 안에서 가로 스크롤합니다. 선택은 URL·같은 탭의 저장소로 유지하며 헤더·푸터 링크와 소식/팝업에서 돌아오는 동선도 선택 지점을 따릅니다. 앱 스크립트가 없으면 일반 지점 링크와 모든 패널을 표시합니다. [현재 홈과 지점 안내 페이지의 캡처 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)를 확인하세요.

## 임시 자료와 탐색

- 실제 브랜드 자산이 없어 프로젝트명을 텍스트 워드마크로 사용했습니다. 공식 로고가 아닙니다.
- 모든 시설·트레이너 이미지는 imagegen으로 생성한 가상 공간·인물이며 사진별로 표시합니다. 실제 지점이나 직원 사진이 아닙니다.
- 주소와 운영시간은 배치 확인용 예시입니다. 실적, 자격, 가격 정보는 추가하지 않았습니다.
- 문의 버튼은 실제 전화나 카카오톡으로 연결되지 않습니다.
- 홈과 지점 안내의 시설은 같은 구성 요소로 PC 3장·태블릿 2장·모바일 1장을 표시하고 4.5초마다 한 칸씩 왼쪽으로 자동 이동합니다. 일시정지·이전·다음 버튼은 없습니다. 모바일 스와이프와 사진 영역의 키보드 좌우 탐색을 유지하며, 마우스/키보드 조작 중에는 멈춥니다. 동작 줄이기 설정에서는 수동 탐색으로 시작합니다. 지점 변경 시 첫 사진으로 돌아가며 사진 1장/0장과 JavaScript 실패를 처리합니다. [자동 슬라이드 검토 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 두 화면의 캡처를 제공합니다.
- 첫 소개 영역의 ‘지점 안내’ 링크는 선택 지점의 별도 페이지로 이동합니다.
- 홈·지점 안내·소식 화면의 푸터 메뉴는 ‘지점 안내’와 ‘소식’ 두 개입니다.
- 헤더·푸터의 지점 안내는 별도 페이지로 이동하며, 홈의 자세히 보기·문의·모바일 문의도 선택 지점을 전달합니다. 트레이너는 상세 페이지에만 표시하며 문의는 같은 지점의 내부 구역으로 연결합니다. 소식은 전체·공지·이벤트 목록과 각 상세로 연결하며 현재 위치의 소식 링크로 분류와 목록 위치를 유지해 돌아옵니다. 사용자 요청에 따라 목록 간격을 줄이고 상세 하단의 문의·목록 복귀 링크는 제거했습니다. JavaScript가 없을 때도 분류·본문과 기본 탐색이 남습니다.
- 지도는 배치 확인용 영역만 표시합니다. 주소·연락처는 두 지점 모두 가상 예시이며 실제 전화나 채널 연결은 없습니다.
- JavaScript가 없어도 본문과 기본 링크, 모바일 메뉴 목록이 남습니다.

## 디자인 기준

색상·글자 크기·간격은 `styles.css`의 공통 변수에서 조정합니다. 사진은 대표 PC 4:3/모바일 16:10, 시설 3:2를 시작 기준으로 사용합니다. 이미지 중심은 각 이미지 프레임에서 조정할 수 있습니다. Pretendard는 공식 배포본을 로컬에서 제공하고 라이선스를 함께 보관합니다.

상세 기준과 승인 이후 순서는 [DESIGN.md](DESIGN.md)에 기록합니다. 현재 상태 검수 결과는 [review/states/checks.json · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에서 확인합니다. 새 소식 검수는 [review/news/checks.json · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 기록합니다. 1차 파일의 `USER_REVIEW_PENDING`과 홈 파일의 `HOME_REVIEW_PENDING`은 사용자 응답 전 촬영 당시의 상태이며, 이후 사용자 확인을 문서에 기록했습니다.

## 팝업과 검수의 한계

아래는 **보존한 정적 원본의 당시 검수 범위**입니다. 실제 DB 연결 홈에는 앞서 기록한 최신 복수 팝업·조건부 수동 링크 정책을 적용합니다. 최신 사용자 확인으로 실제 CMS 홈은 **일반 닫기 후 새로고침·홈 재방문 때 다시 표시하고 오늘 숨김만 유지**합니다. 아래 정적 원본의 ‘탭당 한 번’은 과거 동작이며 현재 제품 정책이 아닙니다. 원본 UI·과거 검수 자료는 재생성하지 않았습니다. [최신 동작 검증 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약).

PC는 `window.open`으로 별도 창을 요청합니다. 브라우저가 새 탭으로 처리할 수 있으며, 자동 열기가 차단되어도 ‘알림 보기’로 직접 열 수 있으면 정상 대응입니다. 모바일은 새 탭 없이 페이지 안의 레이어를 사용하며, 닫기·배경 누르기·Escape로 홈에 복귀합니다. 본문이 길면 내부 스크롤하고 하단 조작줄을 유지합니다. JavaScript가 실패하면 기본 HTML 링크가 같은 탭의 소식 글로 연결됩니다.

기간은 예시로 2026-10-01 00:00부터 2026-11-01 00:00 전까지(한국 시간)입니다. 활성·공개 조건, 한국 시간 다음 날 0시까지 오늘 숨김, 탭당 자동 시도 1회, 수동 재시도와 중복 방지를 검수합니다. 자동 시도 기록과 실제 표시 완료 기록은 구분합니다. 팝업과 지점 탭 배치는 사용자 확인을 받았습니다. 홈의 통합 지점·시설 슬라이드도 사용자 확인을 받았습니다.

기간·공개 조건 검수는 브라우저의 가상 데이터 기준입니다. 서버의 공개 접근 통제나 실제 비공개 자료 보호를 구현한 것이 아닙니다. 자동 검수 시계는 재현을 위해 고정하며, 일반 미리보기는 브라우저의 실제 현재 시각을 사용합니다. 사진 실패와 지도 실패도 검수용 재현이며 실제 외부 지도 호출은 없습니다. 실제 기기·다른 브라우저·외부 서비스 연동은 아직 검수하지 않았습니다.

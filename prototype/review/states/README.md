# 팝업·다지점·빈 데이터·실패 상태 검수

홈 전체를 사용자가 확인한 뒤 수행한 정적 프로토타입 검수다. A 방향과 기존 제품 범위를 유지한다. 백엔드, 관리자, 실제 지도·전화·카카오톡 서비스는 구현하지 않았다.

[브라우저 검수 모음](index.html)에서 미리보기와 캡처를 볼 수 있다. 전체 결과는 [checks.json](checks.json)의 17개 검수 묶음이 통과했다. 이 검수는 홈·별도 지점 안내 분리 후 다시 수행했다. [branch-tab-checks.json](branch-tab-checks.json)은 이전 홈 통합 탭의 7개 검사 이력이며 최신 결과와 합산하지 않는다. 팝업과 통합 탭 배치는 사용자 확인을 받았고, 현재 홈·상세와 통합 시설 슬라이드도 사용자 확인을 받았다. 새 소식 목록·상세는 [news](../news/README.md)에서 별도로 검토한다.

## 통합 지점 탭으로 변경

후속 요청으로 홈에는 지점·시설 미리보기만 남기고 별도 `branches.html`에서 지점 요약·시설·트레이너·위치와 문의를 같은 패널에 묶어 선택한 지점 하나만 표시한다. 기본 예시는 두 지점이다. 데이터 목록에서 탭과 전체 패널을 함께 생성하고, 검수 안에서만 일곱 지점으로 확장해 자동 생성과 모바일 탭 줄의 가로 스크롤을 확인했다. 헤더·푸터 탐색, 새로고침, 지점 직접 링크, 공통 소식과 PC·모바일 팝업의 복귀도 선택 지점을 유지한다.

JavaScript가 실패하면 일반 지점 링크와 모든 패널을 제공한다. 현재 정적 프로토타입은 실제 등록 기능 없이 데이터 추가 후 HTML을 재생성한다. [최신 두 지점별 화면](../branch-pages/index.html)과 [화면 검사](../branch-pages/checks.json)를 확인한다.

## 현재 기본 예시와 모바일 정책

사용자의 2026-10-09 결정에 따라 기본 홈과 이후 모든 예시는 본점·예시점 두 지점을 사용한다. 기존 `preview-two-branches.html`뿐 아니라 `/index.html`, 빈 데이터, 실패 상태도 두 지점이다. 두 지점의 시설·소속 트레이너·주소·운영시간·문의 대상을 구분하며 홈의 공통 전화·카카오톡 버튼은 선택 지점의 상세 문의로 연결한다. 지점과 자료는 모두 가상 예시다.

PC는 기존 별도 창을 유지한다. 모바일(768px 미만)은 같은 홈 위의 네이티브 dialog 레이어로 열어 새 탭을 만들지 않는다. 내용 높이에 맞춘 레이어 안에서 짧은 화면의 본문만 스크롤하며 오늘 숨김·닫기는 계속 표시한다. 열려 있는 동안 배경 스크롤·탐색을 막고 고정 문의 바를 숨긴다. 닫기·Escape·바깥 영역 누르기로 홈의 위치와 진입 링크 포커스를 복원한다. 모바일 소식 글은 같은 탭에서 열리고, 소식에서 돌아와도 두 지점 홈을 유지한다.

JavaScript가 실패하면 HTML의 수동 링크는 같은 탭의 관련 소식 글로 이동한다. 오늘 숨김·표시 기간·공개 조건·탭당 한 번 자동 시도 정책은 PC와 모바일에 공통 적용한다. 화면 폭을 바꿀 때 추가 자동 열기는 없다. PC 크기로 변경되면 레이어를 닫고 스크롤 잠금을 해제한다.

## 팝업 하단 수정

사용자의 하단 여백·닫기 스타일 요청에 따라 기본 창 높이를 760px에서 700px으로 줄이고, 닫기는 테두리와 배경 없는 ‘닫기 ×’ 텍스트형으로 변경했다. 글자 크기는 오늘 숨김과 같은 14px이며 클릭 영역은 44px, 하단 여백은 12px이다. 키보드 Tab 포커스와 Enter 닫기를 유지한다.

PC는 내용이 준비되면 자연 높이를 측정해 창 높이 조절을 요청한다. 브라우저가 새 탭으로 열거나 크기 조절을 제한할 때는 하단 조작줄을 화면 아래에 맞춘다. 모바일은 위 레이어 정책으로 변경했으므로 전체 탭 높이에 맞춰 조작줄을 밀어내지 않는다. [이전 닫기 스타일 검수](popup-refinement-checks.json)는 모바일 정책 변경 전의 이력이다. 아래 캡처와 최신 전체 검수는 모바일 레이어와 두 지점 기본 홈을 기준으로 한다.

## 미리보기와 재현

- 기본 홈: `/index.html` — 본점·예시점 두 지점. 모바일은 레이어, PC 자동 팝업이 차단되면 최근 소식의 ‘알림 보기’를 누른다.
- 두 지점 검수용 주소: `/preview-two-branches.html` — 기본 홈과 같은 구성. 공통 문의로 선택 지점의 별도 상세 페이지에 이동하고 문의 안내 문구를 확인한다.
- 별도 지점 안내: `/branches.html?branch=main`, `/branches.html?branch=second`.
- 빈 데이터: `/preview-empty.html`, `/branches-empty.html`.
- 홈 사진 실패: `/preview-failures.html`. 상세 사진·지도 실패: `/branches-failures.html`.
- 팝업 조건: `/popup.html?case=expired`, `future`, `disabled`, `unpublished`, `missing-post`, `no-image`, `image-failure`.

일반 미리보기는 실제 브라우저 시각을 사용하며 예시 알림의 기간은 2026-10-01 00:00 이상, 2026-11-01 00:00 미만(한국 시간)이다. 자동 검수는 2026-10-09 12:00(한국 시간)을 기준으로 고정하고 경계값을 별도로 검사했다. `npm run review:states`로 재현한다.

## 현재 한계와 다음 단계

공개·기간 조건은 가상 데이터의 클라이언트 동작 검사다. 서버의 접근 통제, 실제 비공개 자료 보호, 실제 서비스 연동을 검증한 결과가 아니다. 자료는 모두 표시된 임시 데이터이며 실제 지점·직원의 사실을 나타내지 않는다.

실제 기기와 Chromium 이외 브라우저는 아직 확인하지 않았다. PC 별도 창 요청이 브라우저에 따라 새 탭으로 처리될 수 있다. PC 자동 차단 자체는 실패 판정이 아니며 수동 접근 가능 여부를 기준으로 확인했다. 모바일은 새 창 요청을 하지 않는다.

팝업과 통합 지점 탭은 사용자 확인을 받았다. 현재 새 소식 목록·상세의 시각 확인을 받은 뒤 다른 화면과 기술 설계를 기존 계획에 따라 구체화하며, 정해지지 않은 기술 스택이나 전체 구현을 임의 확정하지 않는다.

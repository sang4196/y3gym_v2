# Y3GYM 콘텐츠 관리·기술 설계

갱신일: 2026-10-10. 상태: **M2-2 구현·R1 보완 후 독립 재검증 PASS_WITH_WARNINGS. M2-3 트레이너 관리는 기준만 정의한 미착수 상태이며 Git 체크포인트와 설계의 별도 지시 이후 구현한다. 사용자 시각·관리자 사용성 확인은 별도 단계**. [독립 재검증 근거](../backend/review/branches-independent-recheck/README.md).

현재 제품 기준은 [PRD.md](PRD.md), 공개 디자인은 [prototype/DESIGN.md](../prototype/DESIGN.md)다. 이 문서는 기술 선택의 근거와 콘텐츠 관리 설계를 기록한다. 소식·팝업 설정·브랜드/홈·지점/시설의 실제 구현은 §6과 [백엔드 README](../backend/README.md), 미구현 트레이너의 확정 기준은 FR-03·§6, 그 밖의 관리 화면·필드는 후속 설계안으로 구분한다.

**현재 파일 상태:** 문서 정리 시에는 `backend/`가 없었고 과거의 CMS 구현 기록도 확인할 수 없었다. 이후 이번 M1 작업에서 `backend/`를 새로 만들었다. 현재 상태의 근거는 새 소스·마이그레이션·잠금 파일과 [이번 검수 기록](../backend/review/README.md)이며, 과거 기록을 완료 근거로 승계하지 않는다.

후속 사용자 응답 “ㅇㅇ”로 **Django/Wagtail과 소개·지점·트레이너까지 초안 저장 → 미리보기 → 공개로 통일하는 안을 확정**했다. M1 소식·게시글 연동 팝업과 후속 크기·재노출·위치 수정을 거쳐, 최신 **“ok 다음으로 넘어가자”**로 M2의 첫 단위인 브랜드·홈 소개 관리를 진행한다. 이후 역할 분담·자동 반복 진행과 지점 운영 정책을 사용자 답변으로 확정하고 M2-2 지점·시설 관리로 진행했다. [작업 흐름](WORKFLOW.md)을 따른다. 아래 후보 비교는 결정 근거로 보존하며 다른 디자인 방향을 제안하지 않는다.

사용자의 “ㅇㅋ 확인. 다음 진행하자”로 홈의 시설 자동 슬라이드 적용도 확인받았다. 승인된 A 방향과 공개 화면을 기준으로 운영자가 콘텐츠를 관리하는 구조를 구체화한다. 선택한 CMS 이외의 배포 환경·기존 문서의 운영 세부 정책을 자동으로 확정하지 않는다.

## 1. 확정된 기준과 이번 설계의 경계

공개 화면의 현재 기준은 [prototype/DESIGN.md](../prototype/DESIGN.md)다. [이전 PRD](legacy/PRD.previous.md)는 요구를 검토하는 참고 자료이며, 현재 사용자 결정이 우선한다.

| 구분 | 현재 기준 |
| --- | --- |
| 공개 화면 | 홈 → 선택 지점 안내 / 공통 소식 목록·상세. 헤더는 지점 안내·소식·문의, 푸터는 지점 안내·소식 |
| 지점 정보 | 기본 예시는 본점·예시점 두 곳. 지점 탭은 데이터에 따라 늘어나며 시설·트레이너·위치·문의는 해당 지점에 속함 |
| 홈 | 브랜드 소개, 지점 탭과 공통 시설 자동 슬라이드, 공통 최근 소식. 트레이너·위치 상세는 지점 안내에서 제공 |
| 팝업 | PC 별도 창, 모바일 같은 페이지 레이어. 소식 글 연결, 기간·공개 조건, 오늘 숨김, 수동 진입 유지 |
| 편집 범위 | 브랜드·지점·시설·트레이너·소식·팝업·이미지의 고정 콘텐츠 관리. 자유 페이지 빌더는 포함하지 않음 |
| 최근 완료 / 다음 단위 | M2-2 지점·시설은 R1 보완 후 독립 재검증 PASS_WITH_WARNINGS. M2-3 트레이너는 기준만 정의한 미착수. 사용자 시각·관리자 사용성 확인은 별도 |
| 선택한 기술 기반 | Python 3.13.15 + Django 5.2.18 + Wagtail 7.4.3 + PostgreSQL 17.11. 공식 호환성 확인 후 로컬 실행·의존성 고정. 근거·명령은 백엔드 README |
| 반영 시점 | 소개·지점·시설·트레이너·소식 모두 초안 저장 → 미리보기 → 명시적 공개. 현재 소식·브랜드 소개·지점/시설과 본문에서 분리한 팝업 설정을 서버 구현 |
| 아직 선택 전 | 호스팅·비용·운영 담당, 실제 지도 제공자, 각 후속 기능의 운영 세부 정책 |

기존 프로토타입의 소스·검수 자료를 보존한다. CMS는 `backend/`와 기존 M1 전용 로컬 DB를 이어 사용한다. 공개 소식과 홈·팝업은 승인된 프로토타입의 CSS·글꼴을 참조한다. 홈은 보존한 HTML을 읽어 브랜드 소개·지점/시설·팝업·소식 메뉴를 연결하며 최근 소식만 정적 예시다. 실제 `/branches/`는 승인된 배치·CSS·탭·자동 슬라이드를 재사용한다. 트레이너·실제 전화/카카오톡·지도 연동까지 확장하지 않는다.

## 2. 관리자 메뉴와 입력 구조 제안

고객에게 보이는 메뉴와 관리자 메뉴는 역할이 다르다. 관리자는 등록할 콘텐츠를 찾기 쉽게 하고, 고객 화면의 레이아웃·색상·슬라이드 속도를 편집 항목으로 노출하지 않는다. 아래 구성 중 소식·이미지·팝업 설정·브랜드/홈·지점/시설은 실제 구현했다. 트레이너의 필수/선택값·약력·표시 순서와 M2-3 범위는 [FR-03](PRD.md#fr-03-트레이너)·§6에 확정했으나 구현은 미착수다. 구체적인 관리자 사용성과 나머지 제안은 **사용자 미검토**다. 구현된 메뉴도 전체 관리자 사용성의 사용자 승인을 뜻하지 않는다.

| 관리자 메뉴 | 목록 / 편집 화면 | 입력 내용과 반영 위치 |
| --- | --- | --- |
| 브랜드·홈 | 사이트 공통 정보 한 묶음 | 브랜드명·로고, 첫 소개 제목·설명, 대표 사진·대체 설명·사진 중심. 홈 소개와 공통 헤더에 사용 |
| 지점 | 이름·공개 상태·표시 순서 목록 → 지점 편집 | 기본 정보, 시설 사진, 소속 트레이너, 위치·이용안내·문의의 묶음. 홈과 지점 안내가 같은 원본을 사용 |
| 소식 | 전체·공지·이벤트 / 공개·초안 목록 → 글 편집 | 제목, 분류, 짧은 설명, 선택 대표 이미지, 연속된 본문 편집기. 실제 소식 목록·상세·팝업은 공개본 사용. 홈 최근 소식은 미연결 |
| 팝업 설정 — 이번 구현 | **소식 작성/편집 안의 ‘팝업 설정’** | 현재 글에 자동 연결, 사용 여부·한국 시간 시작/종료·상태/이유, ‘팝업 설정 적용’. 별도 팝업 메뉴·수동 URL 입력 없음. 제목·문구·사진은 연결 글 공개본 사용 |
| 이미지 | 업로드·선택·사용처 확인 | 원본, 대체 설명, 표시 중심. 사진 배치 제거와 원본 삭제를 구분 |
| 계정·권한 | 시스템 관리자 전용 | 운영자 계정·권한. 콘텐츠 편집자의 일상 메뉴에서 분리 |

### 지점 편집의 구체적인 묶음

1. **기본 정보:** 지점명, 짧은 소개, 공개 상태, 표시 순서. 본점의 `main` 식별자는 변경하지 않는다. 공개 본점 우선·마지막 철회 허용 규칙은 아래 M2-2 기준을 따른다.
2. **시설 사진:** 사진 선택/업로드 → 제목·설명·대체 설명 → 순서 조정. 홈과 지점 상세에 동일 순서로 반영하며 사진을 두 번 등록하지 않는다. 3:2 표시와 중심을 미리 확인한다.
3. **소속 트레이너 — M2-3 미구현:** 해당 지점에서 트레이너 관리로 진입 → 이름·소속 지점·선택 사진/한줄 소개/직급/약력 편집. 신규 등록은 현재 지점을 미리 선택하되 소속을 명확히 표시한다. 소속 변경은 같은 프로필의 지점 변경으로 처리하며 이동 초안은 현재 공개 소속을 바꾸지 않는다.
4. **위치·이용안내·문의:** 주소·상세주소, 운영시간·휴무·주차·기타 안내, 전화·카카오톡 주소. 지도 입력 방식은 제공자를 결정한 후 추가한다. 없는 채널은 공개 화면에서도 버튼을 만들지 않는다.

지점의 필드와 시설 사진 배치는 한 번의 저장으로 함께 반영한다. 트레이너 프로필·단일 목록 약력은 한 편집·리비전 단위로 만들며 트레이너 편집은 별도 저장 단위임을 표시하여 지점의 저장 버튼과 혼동하지 않게 한다. 같은 지점의 트레이너 표시 순서는 CMS에서 수동 지정한다. 드래그 순서 조정 외에 키보드로 사용할 위/아래 이동을 제공하는 구체적 조작은 제안이다.

## 3. 글쓰기와 공개 흐름

소식은 지점 소유 없이 브랜드 공통으로 관리한다. 제목·분류·짧은 설명·대표 이미지와 본문을 구분한다. 본문은 일반 문서처럼 문단을 이어 쓰고, 굵게·기울임·소제목·목록·링크·본문 이미지 삽입/교체만 제공하는 안이다. 문단마다 블록을 추가·펼치는 과정을 요구하지 않는다.

| 작업 | 관리자에서 보이는 상태 | 고객 화면 |
| --- | --- | --- |
| 새 글을 초안 저장 | 초안 | 목록·상세·홈 최근 소식에 없음 |
| 초안 미리보기 | 권한 있는 운영자에게 수정 내용 표시 | 기존 공개 화면에 영향 없음 |
| 처음 공개 | 공개 | 홈·목록·상세가 같은 공개본 사용 |
| 공개 글을 수정하고 초안 저장 | 공개 중 · 수정 초안 있음 | 기존 제목·본문·이미지·공개일 유지. 연결 팝업도 기존 공개 글 참조 |
| 수정 초안 공개 | 공개 | 새로운 공개본으로 함께 변경 |
| 공개 철회 | 비공개 | 홈·목록·상세·연결 팝업에서 제외 |

편집 화면 하단에는 **초안 저장 / 미리보기 / 공개**를 역할이 다른 조작으로 표시한다. 공개 철회는 별도 동작이다. 미리보기는 승인된 공개 템플릿을 사용하고 관리자 권한을 확인한다. 관리자 로그인 중이라도 일반 고객용 URL은 공개본만 표시한다.

브랜드·지점·트레이너까지 이 방식으로 **통일하기로 확정**했다. 아래 두 안의 비교는 결정 근거이며 예전의 저장 즉시 반영 규칙을 승계하지 않는다.

| 선택안 | 사용 경험 | 영향 |
| --- | --- | --- |
| **초안·미리보기 후 공개로 통일 — 채택** | 소개·시설 사진·프로필도 먼저 저장하고 실제 배치 확인 후 공개 | 미완성 수정이 노출되지 않고 조작 의미가 일정함. 콘텐츠별 공개본·초안 및 관련 데이터 처리가 필요 |
| 소식만 초안, 나머지는 저장 즉시 반영 | 운영시간·소개·프로필 변경을 저장 즉시 고객 화면에 반영 | 빠른 수정 가능. 저장 화면마다 반영 시점을 명확히 안내해야 하며 수정 중인 공개 콘텐츠의 보호 범위가 좁아짐 |

통일안을 택해도 여러 콘텐츠를 한꺼번에 배포하는 기능이나 다단계 승인 절차를 추가하지 않는다. 팝업 사용 여부·기간 변경은 **‘팝업 설정 적용’**으로 별도 반영하도록 사용자 지시로 확정했다. 본문 입력을 제출하지 않고 새 초안을 공개하지 않는다. 관리자 사용성 자체의 사용자 확인은 별도로 남는다.

## 4. 데이터 관계와 공개 경계

다음은 제품 전체의 개념 모델이다. 소식·이미지·리비전은 M1, 글당 팝업 설정은 `0002_popupsetting`, 브랜드·홈 한 묶음은 이번 `0003_brandcontent`에서 마이그레이션했다. 지점·시설은 `0004_branch_facility`에서 추가했다. 트레이너 테이블·관리는 미구현이다.

| 데이터 | 소유 / 관계 | 주의할 점 |
| --- | --- | --- |
| 사이트 정보 | 사이트 공통 1묶음 | 홈의 지점·소식 목록을 따로 복제하지 않음 |
| 지점 | 시설 사진 여러 개, 트레이너 여러 명 | 안정적인 식별자와 표시 순서를 구분. 이름 변경으로 기존 지점 링크가 깨지지 않게 함 |
| 시설 사진 배치 | 지점 하나 + 이미지 하나 | 제목·설명·대체 설명·순서·사진 중심을 배치별로 관리 |
| 트레이너 — 미구현 | 공개 시 정확히 한 지점 + 단일 약력 목록 | 미완성 초안 허용. 프로필과 소속 지점이 모두 공개일 때만 표시하고 소속 이동 초안은 현재 공개 소속을 유지. 지점 비공개 시 원본 프로필·자체 공개 설정 보존 |
| 소식 | 브랜드 공통 | 공개본과 수정 초안 분리. 분류는 공지·이벤트 |
| 팝업 설정 | 소식과 1:1, 본문 리비전과 별도 테이블 | 사용·시작·종료·설정 버전. 서버 시각과 연결 글 공개 여부를 검사. 제목·문구·사진은 현재 공개 리비전 참조 |
| 이미지 자산 | 여러 콘텐츠에서 재사용 가능 | 초안·공개본의 사용처를 구분. 공개 파일을 덮어쓰지 않고 새 파일 참조로 교체 |
| 관리자 계정 | 콘텐츠 운영자 / 시스템 관리자 | 고객 계정을 만들지 않음. 구체적 권한은 CMS 검증 단계에서 정리 |

공개 HTML을 만드는 조회와 향후 공개 API가 필요할 때의 조회는 같은 공개 조건을 사용한다. 처음부터 별도 프런트엔드 서비스나 불필요한 API 전체를 만들지는 않는다. 지점·소식·팝업 각각에서 공개 상태를 중복 해석하지 않도록 공통 조회 경계를 둔다.

초안 미리보기와 미공개 이미지의 원본·변환본·관리자 썸네일은 권한을 확인한다. 공개 이미지는 현재 공개 사용처가 있을 때만 제공하고, 마지막 사용처를 철회하면 새로운 무권한 요청을 차단하는 구조를 검증한다. 단순히 파일명을 숨기거나 주소에 서명을 넣는 것을 공개 상태 검증의 대체로 취급하지 않는다. 저장소·이미지 변환·캐시를 포함한 실제 경로에서 확인해야 한다.

팝업은 서버 기준 `시작 <= 현재 < 종료`, 활성 상태, 연결 소식 공개 조건을 적용한다. 직접 URL 접근에도 같은 조건을 적용한다. 입력 시각은 한국 시간으로 표시하며, PC/모바일 표시 방식·자동 차단 시 수동 진입·오늘 숨김은 승인된 프로토타입의 동작을 유지한다.

## 5. CMS와 앱 구성 비교

아래는 2026-10-10 후보 비교와 공식 문서 참조다. 추천 이유를 설명한 뒤 사용자 “ㅇㅇ”로 Django/Wagtail + PostgreSQL을 선택했다. 기존 프로젝트 스택을 자동 승계한 결정이 아니다. 이번 M1에서 공식 호환성을 확인하고 Python·Django·Wagtail과 DB 버전을 고정했다. 정확한 파일과 공식 근거는 [백엔드 실행 안내](../backend/README.md#버전과-로컬-준비)에 있다. 미채택 비교안은 이력이다.

| 항목 | Django + Wagtail + PostgreSQL — 채택 방향 | Next.js + Payload + PostgreSQL — 미채택 비교 이력 |
| --- | --- | --- |
| 구성 | Python 앱 안에서 고객용 HTML과 CMS 관리자 제공 | TypeScript/Next.js 앱 안에서 고객 화면과 Payload 관리자 제공 |
| 기존 공개 UI 연결 | 승인된 HTML을 서버 템플릿으로 옮기고 CSS·상호작용 유지 | 승인된 HTML을 화면 컴포넌트로 옮기고 CSS·상호작용 유지 |
| 글쓰기 | 단일 RichTextField의 서식·이미지 기능을 필요한 범위로 제한 | 단일 리치 텍스트 필드의 서식·업로드 기능을 필요한 범위로 제한 |
| 초안·미리보기 | 콘텐츠 모델에 미리보기·버전·초안 기능을 명시적으로 구성 | 컬렉션에 버전·초안·미리보기와 읽기 권한을 명시적으로 구성 |
| 지점 관리 | 지점·시설·트레이너 관계와 입력 패널 구성 필요 | 같은 관계와 입력 필드 구성 필요 |
| 공통 추가 작업 | 한국어 입력 경험, 관계 데이터 공개 규칙, 이미지 접근 제어, 팝업 조건, 저장 충돌 검증 | 동일. Payload 기본 제공 기능만으로 제품의 공개 정책이 충족된다고 가정하지 않음 |
| 선택에 맞는 경우 | 고정 정보 홈페이지와 콘텐츠 운영이 중심이며 Python 운영이 가능할 때 | 개발·유지보수 팀이 TypeScript/Next.js를 주로 사용하거나 그 생태계 통일을 원할 때 |

**추천 이유:** 현재 화면은 고정된 정보 구조와 소규모 상호작용이 중심이다. 승인된 HTML을 서버 템플릿으로 연결하고 CMS의 입력·초안 기능을 활용하는 구성이 적합하다고 판단한다. Wagtail은 단일 본문 서식과 이미지 삽입을 제공하며, 별도 콘텐츠 모델에도 미리보기·초안 기능을 구성할 수 있다. [공식 본문 편집 문서](https://docs.wagtail.org/en/stable/advanced_topics/customization/page_editing_interface.html#rich-text-html), [콘텐츠 미리보기·초안 문서](https://docs.wagtail.org/en/stable/topics/snippets/features.html).

미채택 비교안의 기록도 보존한다. 당시 Payload는 React/TypeScript와 Next.js App Router 기반 관리자, 공개본과 수정 초안 분리, 업로드 읽기 권한 구성을 비교했다. [공식 관리자 문서](https://payloadcms.com/docs/admin/overview), [본문 편집 문서](https://payloadcms.com/docs/rich-text/overview), [초안 문서](https://payloadcms.com/docs/versions/drafts), [업로드 문서](https://payloadcms.com/docs/upload/overview#access-control). 이 기록은 새로운 후보 선택 요청이 아니다.

두 후보 모두 실제 초안 미디어 보호·공개 사용처 판단은 이 제품의 규칙에 맞춰 구현하고 검증해야 한다. Wagtail의 이미지 서명 URL만으로 이러한 규칙이 구현됐다고 판단하지 않는다. [공식 이미지 제공 방식](https://docs.wagtail.org/en/stable/advanced_topics/images/image_serve_view.html).

**M1 제외:** 홈 최근 소식·팝업의 CMS 연결, 브랜드·지점·시설·트레이너 관리, 전체 운영 권한/삭제/복원 정책, 실제 자료·지도·문의·외부 저장소·운영 배포. 문의 지점 링크는 기존 두 지점 예시를 유지한다. DB에는 소식 테스트 자료만 준비하며 지점 등록 모델이 생긴 것은 아니다.

버전·실행법·계정 파일은 [백엔드 README](../backend/README.md), M1 검사·한계는 [M1 검수 기록](../backend/review/README.md)에 기록한다. M1 제외 항목과 아래 팝업 단계의 중지 범위는 당시 기록이다. M2-1만 진행한 당시 범위도 이력이다. 이후 최신 사용자 위임·지점 정책 답변에 따라 M2-2를 진행한다.

**당시 M1 검증**은 서버 17개 통과, 브라우저 8개 흐름 `PASS_WITH_WARNINGS`다. 중복 이미지 업로드 확인에서 Wagtail 기본 탭 오류가 남아 있으나 작성·이미지 교체·공개·철회 흐름은 통과했다. 미해결 사항으로 기록하며 전체 관리자 완료나 사용자 승인으로 확대하지 않는다. 이번 팝업 작업은 기존 17개를 포함한 서버 33개, 새 브라우저 9개 흐름을 통과했다. 새 검사는 중복 이미지 업로드를 재현하지 않았으므로 당시 오류를 해결했다고 보고하지 않는다.

실제 브랜드 자료·지도 제공자·호스팅 결정은 M1을 막지 않는다. 이후 DB 예시도 본점·예시점 두 곳을 유지하고, 가상 자료를 운영 자료로 자동 전환하지 않는다.

### 완료 이력: 게시글 연동 팝업 설정과 실제 노출

- **상태 분석:** M1 시작 당시 팝업은 정적 가상 데이터·클라이언트 검수뿐이었다. 모델·관리자·서버 노출 연결이 없었고 M1에서 후속으로 분리했다. 기존 별도 팝업 관리자 제안은 미검토안이며 최신 지시의 **소식 편집 내 설정**으로 구체화했다.
- **실제 저장:** `PopupSetting`은 Post와 1:1이며 본문 리비전에 포함하지 않는다. 사용 시 기간 필수·시작<종료, 한국 시간 입력. 게시 권한과 Wagtail 잠금을 확인하고 Post 행 잠금·설정 version으로 동시 적용을 보호한다. 본문의 기존 리비전 충돌 검사도 유지한다.
- **편집 동작:** 새 글 먼저 초안 저장. 이후 본문 아래 ‘팝업 설정’에서 별도 적용. 입력 필드는 본문 form 제출 대상에서 제외하고 전용 요청으로 저장한다. 본문 입력은 유지하며 나중의 초안 저장·게시도 팝업을 되돌리지 않는다. JavaScript가 없으면 편집 탭을 보존한 채 새 탭의 설정 form을 사용한다.
- **공개 경계:** 홈과 `/popups/<글 ID>/`, `/popups/<글 ID>/data/`는 공통 서버 판정 `사용 && 글 공개 && 시작<=현재<종료`를 사용한다. 공개 리비전의 제목·짧은 설명·대표 사진만 사용한다. 종료·팝업 해제는 게시글 공개를 철회하지 않는다.
- **확정 정책:** 중첩 전체 허용, 개수 제한 없는 전체 자동 노출, 최초 글 등록 순서(첫 초안 리비전 시각, 같은 시각은 ID), 전 지점 공통. 최신 사용자 확인으로 **일반 닫기 후 새로고침·홈 재방문마다 다시 자동 노출**한다. 이전 탭당 한 번 플래그는 자동 노출 조건에서 제외한다. PC 글별 별도 창/이름 재사용, 모바일 한 개씩 순차 레이어를 유지하며 화면 크기 변경만으로는 다시 시도하지 않는다. 모바일은 다음 레이어 직전에 서버를 재확인한다.
- **복구:** 평소 ‘알림 보기’ 제거. 자동 차단·로딩 실패 때만 글별 텍스트 복구 링크. 새로고침에서는 다시 자동 시도하고 실패하면 복구 링크를 제공한다. 세션 기록 저장 실패는 자동 노출을 막지 않는다. 명시적인 오늘 숨김만 글별 한국 시간 다음 날 0시까지 적용하며 저장 실패는 안내한다. JavaScript 실패 시 서버 HTML의 공개 글 링크와 기본 탐색 유지.
- **보존·연결:** `prototype/` 원본과 기존 검수는 재생성하지 않는다. `home.py`가 홈 HTML을 읽어 URL·팝업 진입만 변경한다. `scripts/serve-prototype.py`는 기존 8767 홈만 8768 실제 홈으로 연결한다. 지점·과거 검수는 기존 파일로 제공한다.
- **제외:** 홈 전체 CMS화, 별도 팝업용 문구/사진 입력, 브랜드·지점/시설·트레이너 관리, 외부 서비스·운영 배포. 관리자 사용성 사용자 승인, 실제 기기·다른 브라우저는 완료로 보고하지 않는다.

당시 검증 명령·결과·캡처와 남은 한계는 [팝업 검수 기록](../backend/review/popups/README.md)에 모았다. 버전은 변경하지 않았다. 커스텀 패널·관리자 URL은 [Wagtail 패널](https://docs.wagtail.org/en/stable-7.4.x/reference/panels.html)·[관리자 URL 훅](https://docs.wagtail.org/en/stable-7.4.x/reference/hooks.html#register-admin-urls), 입력 시각 처리는 [Django 시간대 폼](https://docs.djangoproject.com/en/5.2/topics/i18n/timezones/#time-zone-aware-input-in-forms)의 공식 문서와 기존 설치 버전을 확인했다.

**복수 창 크기 수정:** 사용자 실제 화면에서 창 폭 불일치·하단 과도한 여백이 발견됐다. CMS 전용 크기 계산·CSS를 수정하고 화면이 표시되는 Chromium에서 모든 창의 실제 경계와 내용 높이를 다시 검증한다. 이전 headless 통과를 실제 크기 검증으로 확대하지 않는다. [수정·검증·미실행 항목](../backend/review/popup-sizing/README.md)에 별도로 기록하며 DB·관리자 정책·노출 순서·다음 마일스톤은 변경하지 않는다. 이후 재노출·위치 수정 후 사용자 “ok 다음으로 넘어가자”로 후속 진행을 확인했다. Whale 직접 검증은 미실행이다.

**새로고침·재방문 재노출 수정:** 일반 닫기와 오늘 숨김을 분리하는 최신 사용자 확인을 반영했다. `home-popups.js`의 세션 전체 자동 시도 차단을 제거했다. 뒤로가기 캐시 복원은 새 서버 공개/기간 판정으로 홈을 갱신하며, 열린 PC 창은 이름으로 재사용한다. [별도 재노출·크기 회귀 기록](../backend/review/popup-revisit/README.md)에 이번 실행 결과를 구분한다. 기존 검수는 이전 정책 당시의 이력으로 보존하며 UI·DB·관리자·다음 마일스톤은 확장하지 않는다.

**PC 중앙 랜덤 배치 수정:** 최신 사용자 요청으로 `popup-sizing.js`에 작업 영역·중앙 분산·가장자리 여백 계산을 추가했다. 홈에서 중앙 구역을 섞어 시작 좌표를 지정하고, 같은 출처·실제 자식 창·글 ID를 확인한 메시지로 동일한 랜덤 기준점을 전달한다. 창 크기 확정 후 실제 창 테두리로 생긴 좌표 차이를 제한된 초기 재시도로 보정한다. 홈이 요청한 모니터와 실제 열린 모니터가 다르면 실제 창의 작업 영역 안에서 중앙을 맞춘다. 이동을 강제하지 못하는 브라우저에서는 무한 재시도하지 않는다. 준비 완료는 초기 크기·위치 보정 이후 전달한다. [위치 검수·캡처·재노출 회귀](../backend/review/popup-position/README.md)를 별도로 기록하고 기존 프로토타입과 검수는 보존한다. 모바일·DB·관리자·다음 마일스톤은 변경하지 않는다.

- **데이터 경계:** 기존 소식과 동일한 리비전·미디어 보호·CSRF·권한·편집 잠금·행 잠금/오래된 폼 거부를 재사용한다. 공개한 브랜드/소식 중 어느 한 사용처라도 있는 이미지의 변환본만 익명 제공한다. 원본·초안·미사용 이미지는 계속 보호한다. 브랜드 삭제/복원 정책은 미결정이며 이번에는 삭제 동작을 제공하지 않는다.

### 이번 단위: M2-2 지점·시설 관리

- **모델·편집:** `Branch` + `FacilityImage(Orderable, ParentalKey)`와 `ClusterableModel`을 사용한다. 지점명·소개·주소·운영시간·선택 전화/카카오톡 모의 안내·표시 순서, 시설 사진/제목/설명/대체 설명/순서/중심을 한 편집·리비전 단위로 관리한다. 버전·기술 스택은 유지했다.
- **확정 정책:** 공개 본점 `main` 1곳을 항상 첫 순서·새 방문 기본값으로 한다. URL·같은 탭의 명시 선택은 유지하고 본점 비공개 시 첫 유효 공개 지점을 표시한다. 추가 지점은 공개본의 표시 순서·ID 순이다. 본점 식별자를 폼에서 변경하지 않으며 교체·삭제/복원 절차는 추가하지 않는다.
- **공개 필수값:** 미완성 초안 저장 허용, 공개 시 지점명·주소·운영시간만 필수·공백 거부. 시설 이미지 없는 항목은 편집기 안내와 함께 초안에 보관하고 공개 갤러리에서 제외한다. 사진/트레이너/선택 연락수단이 없으면 해당 영역·버튼을 숨긴다.
- **철회·선택:** 마지막 공개 지점도 철회 가능하다. 0곳이면 준비 중 안내·브랜드/소식 탐색을 유지하고 공통·모바일 문의 버튼을 숨긴다. 홈·실제 `/branches/`·소식·팝업이 같은 공개 지점 목록을 사용하며 신규 지점도 동선 전체에서 유지한다. 문의는 선택 지점의 등록된 채널만 모의 안내로 제공한다.
- **공개 경계:** `live_revision.as_object()`로 지점과 시설 자식 전체를 함께 복원한다. 수정 초안의 주소·표시 순서·사진 추가/삭제/재정렬/교체가 공개본에 새지 않게 한다. 시설 공개 이미지 사용처를 브랜드·소식과 합쳐 미디어 접근을 판정한다. 권한 미리보기·private/no-store, 모델 권한·CSRF·Wagtail 잠금·행 잠금/오래된 폼 검사를 재사용하며 실제 동시 저장/공개도 검사한다.
- **화면·보존:** 홈은 소개 → 지점 탭/시설 → 기존 정적 최근 소식 → 푸터를 유지한다. 지점 안내는 요약·시설·위치/운영시간·문의이며 CMS 트레이너 0건으로 해당 영역을 숨긴다. 기존 색상/글꼴/간격·탭과 4.5초/600ms·3/2/1장 슬라이드 코드를 재사용한다. JavaScript가 없으면 모든 공개 지점의 주소·운영시간·기본 링크가 남는다. 원본 프로토타입·생성 HTML·기존 검수는 재생성하지 않는다.
- **로컬 자료:** 기존 두 지점의 `main`/`second` 이름·주소·운영시간·가상 사진/연락처를 임시 자료 표시와 함께 초기화한다. 멱등 명령은 지점이 이미 있으면 콘텐츠·리비전·미디어를 덮어쓰지 않는다. 쓰기 검수는 별도 테스트 DB·임시 미디어/계정에서 수행한다. 기존 소식/팝업/브랜드/계정·비공개 미디어의 사전/사후 해시를 구분한다.
- **제외:** 트레이너 CMS, 홈 최근 소식 CMS화, 실제 전화/카카오톡/지도, 본점 교체·삭제/복원·예약게시·계정관리 확대, 배포·새 비용·외부 변경·Git 반영. 자체 검수 완료를 독립 검증이나 사용자 시각 승인으로 확대하지 않는다.

실제 명령·캡처·실패 이력·한계는 [지점 검수 기록](../backend/review/branches/README.md)에 둔다. ### 다음 단위: M2-3 트레이너 관리

**미착수.** 이번에는 [PRD FR-03](PRD.md#fr-03-트레이너)의 사용자 확정 기준으로 범위·완료 기준만 정의한다. M2-2 종료 문서 검토와 Git 체크포인트를 마치고 **설계의 별도 구현 지시 이후** 착수한다. 트레이너 소스·모델·마이그레이션·DB 자료가 이미 존재하거나 아래 검사를 수행한 것으로 해석하지 않는다.

**구현 범위와 완료 기준**

- **소속·편집 단위:** 프로필은 한 지점에 소속되고 프로필·약력은 한 편집·리비전 단위다. 지점에서 소속 트레이너 관리로 진입하며 지점·시설과 **별도 저장 단위**임을 화면에서 명시한다. 같은 프로필의 소속 이동을 제공하고 복제로 처리하지 않는다.
- **입력·표시 순서:** 공개 시 이름·소속 지점만 필수, 사진·한줄 소개·직급·약력은 선택이다. 미완성 초안 저장을 허용하고 비어 있는 선택 영역은 숨긴다. 약력은 **경력·자격·수상 분류 없는 단일 목록**이다. 같은 지점의 트레이너 표시 순서는 **CMS에서 수동 지정**하며 순서 수정 초안도 공개본과 분리한다.
- **공개 흐름:** 초안 저장 → 권한 있는 미리보기 → 명시적 공개·철회. 관리자 로그인 중에도 일반 고객 URL은 현재 공개 리비전만 표시한다. 미리보기의 권한·`private, no-store`와 필수값 오류 시 입력 보존을 기존 패턴으로 검증한다.
- **지점별 공개 조회:** 실제 지점 상세에서 **선택 지점의 공개 프로필만** 연결하며 **프로필과 소속 지점이 모두 공개**여야 표시한다. 지점 철회 시 해당 프로필을 고객 화면에서 숨기되 원본·자체 공개 설정은 보존한다. 소속 이동 초안은 현재 공개 소속에 영향을 주지 않고 명시적 공개 후 새 소속에만 표시한다. 프로필 0건이면 트레이너 영역을 숨긴다.
- **승인 화면 재사용:** [디자인 문서](../prototype/DESIGN.md#배치와-반응형)의 기존 트레이너 카드·PC/태블릿 2열·모바일 1열과 사진 **4:5**를 재사용한다. 사진·한줄 소개·직급·약력의 빈 선택 영역 숨김과 긴 이름/목록의 반응형을 확인한다. 홈 구성·고객 메뉴·문의 동선은 기존 기준을 유지한다.
- **미디어·저장 경계:** 기존 이미지 공개 사용처 판정과 행 잠금·오래된 폼/동시 저장 보호를 재사용하고 회귀 검증한다. 프로필·소속 지점의 이중 공개 조건을 사진 사용처에도 적용하며 소식·브랜드·시설과 공유한 이미지의 마지막 공개 사용처 철회, 초안 사진·원본·변환본·관리자 썸네일의 무권한 접근을 확인한다. 소속 이동·약력/수동 순서·사진 수정의 초안 누출과 저장/공개/철회 교차 요청에서 최신 리비전 보존을 검사한다.
- **자료·검증 보존:** 실제 자료가 없으면 기존 가상 인물·사진을 **임시 자료임을 명확히 표시**해 사용할 수 있다. 확인되지 않은 경력·자격·실적은 만들지 않는다. 쓰기 검수는 별도 테스트 DB·임시 미디어/계정에서 수행하고 실제 앱·원본 프로토타입·이전 검수·비밀·Git index를 보존한다. 실제 지점 상세의 PC/모바일·지점 선택·미리보기·공개/철회와 기존 소식/브랜드/지점·팝업 회귀를 확인하고 자체 검사·독립 검증·사용자 승인을 구분해 보고한다.

**제외·미구현:** 프로필 삭제/복원, 운영 계정·권한 관리 확대, 홈 트레이너, 새로운 고객 메뉴·별도 공개 프로필 페이지, 홈 최근 소식 CMS화, 실제 지도·전화·카카오톡, 운영 배포·새 비용·외부 서비스·기술 스택 변경. M2-3 기준 정의는 이 제외 항목의 구현 승인이나 사용자 시각/관리자 사용성 승인으로 확대하지 않는다.

## 7. 지금 결정할 항목과 나중에 확인할 항목

**사용자 확인으로 확정한 기준**

- CMS 기반: Django/Wagtail + PostgreSQL.
- 브랜드·지점·트레이너 반영: 소식과 함께 초안·미리보기 후 공개로 통일.
- 트레이너: 공개 필수 이름·소속 지점, 사진·한줄 소개·직급·약력 선택, 미완성 초안 허용, 분류 없는 단일 약력 목록, 지점 내 CMS 수동 표시 순서. M2-3은 위 기준 정의까지이며 미착수다.

**해당 기능의 구현 전에 구체화할 사항**

- M2-2의 공개 본점 우선·표시 순서·마지막 공개 지점 철회 허용·공개 필수값은 사용자 답변으로 위에 확정 반영했다. 본점 교체·삭제/복원은 후속 정책으로 남긴다.
- 브랜드는 이번 사용자 응답으로 미완성 초안 저장 허용·공개 시 브랜드명/소개 제목 필수로 확정했다. 지점은 이름·주소·운영시간만 공개 필수이며 사진·트레이너·연락처는 선택으로 확정했다.
- 팝업의 중첩·개수·순서·공통 범위·별도 적용은 이번 사용자 응답으로 확정했다. 별도 팝업용 문구·사진 입력은 이번 범위에서 구현하지 않았다. 현재는 연결 글 공개본을 재사용하며 추가 편집 경험은 구체화 전이다.
- 게시글의 공개일 변경·목록 정렬 정책, 운영자 삭제·복원 범위. 현재 프로토타입의 목록 10건은 초기 기준이다.
- 지도 제공자와 실제 지점별 전화/카카오톡 주소. 현재는 어떤 외부 서비스도 연결하지 않는다.
- 호스팅 예산, 운영 담당, 도메인, 업로드 저장소, 백업·복구 방식. CMS 사용 조건과 서버·DB·저장소의 운영 비용을 구분해 확인한다.

이 항목들은 기존 문서에서 임의로 승계하지 않는다. 소식 CMS의 로컬 구현이 공개일 변경·삭제/복원·최종 운영 권한이나 운영 배포 정책을 확정하지 않는다. 관리자 사용성·시각 확인은 구현·독립 검증·Git 반영과 구분한다. M2-3 구현은 Git 체크포인트와 설계의 별도 지시 이후 진행한다. 전체 제품의 미결정 사항은 [PRD](PRD.md#6-이후-진행과-미결정-사항)에 모은다.

## 1. 목적과 사용자

브랜드·지점·시설·트레이너를 소개하고 방문자를 선택 지점의 전화·카카오톡 문의로 연결하는 공식 홈페이지를 만든다. 운영자는 개발자 도움 없이 고정된 화면의 콘텐츠를 관리한다. PT 운영관리 제품과 분리한다.

| --- | --- |
| 처음 방문한 고객 | 홈 소개·선택 지점 시설 → 별도 지점 안내 → 이용안내·위치 → 해당 지점 문의 |

헤더는 **지점 안내·소식·문의하기**, 푸터는 **지점 안내·소식**이다. 공개 CMS 헤더의 브랜드명·선택 로고는 `branch` 없는 공통 홈으로 이동한다. 쿼리 없는 홈 진입·새로고침은 저장된 지점 선택과 기본 표시를 유지하면서 주소를 강제로 지점화하지 않는다. 명시 지점·사용자 탭 선택·문의 동선은 기존 지점 전달을 유지하며 푸터·breadcrumb·팝업 브랜드는 이번 범위 밖이다. 별도 트레이너 메뉴·페이지를 두지 않는다. 지점 안내 메뉴와 첫 소개의 ‘지점 안내’ 링크는 별도 페이지로 이동한다. 홈에는 트레이너·주소·운영시간·지도 상세를 표시하지 않는다.

## 4. 기능 요구사항

### FR-01 브랜드와 공통 콘텐츠

- 브랜드명·로고·대표 사진·소개 제목·설명을 관리한다. 레이아웃·메뉴·색상을 자유 편집하는 페이지 빌더를 만들지 않는다.
- **M2-1:** 사이트 공통 한 묶음으로 브랜드명·선택 로고·소개 제목/설명·선택 대표 사진/대체 설명/사진 중심을 관리한다. 초안 → 권한 있는 홈 미리보기 → 명시적 공개·철회. 공개 홈·실제 소식/팝업의 공통 브랜드 표시는 현재 공개 리비전만 사용한다. M2-2에서 실제 지점 안내·홈의 지점/시설도 현재 공개 리비전으로 연결했다. 정적 원본은 보존한다.
- **이번 사용자 확인:** 공개 시 브랜드명·소개 제목만 필수이며 공백만 입력한 값은 허용하지 않는다. 설명·로고·대표 사진은 선택이다. 미완성 초안 저장은 허용한다. 로고가 없으면 텍스트 브랜드명, 대표 사진이 없으면 기존 텍스트 중심 배치를 사용한다. 공개본이 없으면 준비 중 안내와 기본 지점·소식 탐색을 남긴다.

### FR-02 지점·시설

- 본점과 추가 지점은 동일한 콘텐츠 구조를 사용한다. **현재와 이후 기본 예시는 본점·예시점 두 개**다. 예시점은 실제 등록 지점이 아니다.

### FR-03 트레이너

- 트레이너는 한 지점에 소속되며 **지점 안내에서만** 소개한다. CMS와 실제 지점 상세 연결은 **M2-3 로컬 구현**이며 범위·완료 기준은 [구현 계획](IMPLEMENTATION-PLAN.md#다음-단위-m2-3-트레이너-관리), 실제 자체 검사·새 캡처·보존과 한계는 [트레이너 검수 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 둔다. [초기 독립 검증 FAIL · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)의 최신 초안 검색 불일치를 [M2-3-R1 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에서 보완했다. 이후 [독립 재검증 PASS_WITH_WARNINGS · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)로 F01/P2·W02~W04 해결·새 차단 결함 없음을 확인했다. W01 기존 포맷 경고는 유지하며 관리자 사용성 승인은 별개다. **2026-10-10 사용자 시각 승인:** 검토한 [PC](../backend/review/trainers/regressions-final/combined/trainer/short-biography-desktop-section.png)·[모바일](../backend/review/trainers/regressions-final/combined/trainer/short-biography-mobile-section.png)의 직급·약력 배치를 “이 배치로 유지”로 확정했다. 이 선택정보 배치 승인과 관리자 사용성·실제 기기·배포 승인은 별개다.
- **사용자 확정:** 공개 시 **이름·소속 지점만 필수**다. 사진·한줄 소개·직급·약력은 선택이며 미완성 초안 저장을 허용한다. 비어 있는 선택 영역은 고객 화면에서 숨긴다.
- **약력은 항목을 나열하는 단일 목록**으로 관리한다. 경력·자격·수상 등으로 분류하지 않는다. **같은 지점의 트레이너 표시 순서는 CMS에서 수동 지정**한다.
- 관리자 목록의 이름·소속과 검색의 이름·소개는 최신 초안 기준이다. 검색은 최신 리비전이 없을 때만 현재 모델 값을 사용하며 최신 초안의 빈 값으로 이전 공개 값을 검색하지 않는다. 소속 필터·검색·공개 상태 필터·페이지 이동을 함께 유지한다.

M1 당시 홈 최근 글은 정적 예시였고 M2-4에서 기존 공개 조회를 재사용해 연결했다. 분류·제목·선택 요약·최초 공개 날짜·실제 상세 링크를 A 행에 표시하고 0건이면 “등록된 소식이 없습니다.”를 안내한다. 선택 지점·JavaScript 없는 기본 탐색을 유지하고 초안/철회 글은 노출하지 않는다. 팝업은 후속 M1 작업에서 실제 공개 글과 연결했으며 M2-2에서는 공통 지점 선택을 실제 공개 지점 목록으로 통일했다.

### FR-06 공개 흐름과 미디어

- **브랜드·지점/시설·트레이너·소식 모두 초안 저장 → 미리보기 → 명시적 공개**로 통일하기로 결정했다. 이전의 소개·지점·트레이너 저장 즉시 반영 정책은 채택하지 않는다.
- 새 초안은 고객 화면에 노출하지 않는다. 공개 콘텐츠를 수정 초안으로 저장해도 기존 공개 제목·본문·사진·날짜를 유지한다. 미리보기는 권한 있는 운영자에게 수정본을 보여주고 일반 고객 URL은 공개본만 제공한다.
- 공개 철회 시 관련 공개 목록·상세·연결 팝업에서 제외한다. 팝업의 사용 여부·기간 조작은 콘텐츠 공개와 구분한다. 2026-10-11 사용자 직접 확인은 게시글 연결 팝업의 관리자 기간 운영→공개 화면 연결 흐름에 한정하며 관리자 전체 조작 승인은 아니다.
- 초안 이미지·원본·관리자 썸네일의 무권한 접근을 차단한다. 공개 파일 덮어쓰기 대신 새 파일 참조로 교체하고 현재 공개 사용처를 기준으로 제공한다. 마지막 공개 사용처 철회 후 새 무권한 요청을 차단하는 경계를 검증해야 한다.
- **M1에서는 소식에 한해** 공개 리비전 분리·권한 있는 미리보기·이미지 직접 접근 통제·파일 덮어쓰기 방지·오래된 화면 및 실제 동시 저장 충돌을 구현하고 검증한다. 브랜드·지점·트레이너·팝업, 최종 운영 권한·삭제/복원·배포 캐시 정책까지 완료한 것은 아니다. 수행 결과와 한계는 [M1 검수 기록](../backend/review/README.md)을 따른다.
- M2-1은 같은 공개본·미디어·저장 충돌 경계를 브랜드·홈 소개에 적용한다. 브랜드와 소식의 공유 이미지 사용처도 함께 판정한다. 전체 지점/트레이너 공개 통제·최종 운영 권한·삭제/복원 정책까지 완료한 것은 아니다. [브랜드 검수 기록 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에서 이번 실행과 기존 검사를 구분한다.

- **M2-2:** 지점과 시설 자식 목록을 같은 공개 리비전에서 복원한다. 주소·순서·시설 추가/삭제/재정렬·사진 변경의 초안이 공개본에 새지 않는다. 지점 시설의 공개 이미지 사용처를 소식·브랜드와 합쳐 마지막 공개 사용처 철회 후 익명 변환본 요청을 차단한다. 미리보기 권한·`private, no-store`, CSRF·모델 권한·잠금·오래된 폼/동시 저장 경계는 기존 패턴을 재사용한다. 로컬 자체 검수와 한계는 [지점 검수 기록 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 둔다.

M2-2는 [초기 독립 검증 FAIL · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약) → [R1 보완 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약) → [독립 재검증 PASS_WITH_WARNINGS · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)로 종료 상태를 갱신한다. 지점·브랜드·소식의 실제 행 잠금으로 양쪽 교차 순서의 초안 저장/공개·철회, 최신 리비전·본문/시설 보존과 권한/CSRF/hooks를 독립 재실행해 F01·F02·W01 해결·차단 결함 없음을 확인했다. 기존 `backend/review/workflow-01/verify.py` 전역 포맷 경고와 실제 기기·Whale·한국어 IME·운영 환경·사용자 시각/관리자 사용성 미검증은 남는다. 이전 보고·캡처는 당시 기록으로 보존하며 M2-2 종료 문서 작업에서는 제품 검사를 재실행하지 않았다.

- **M2-3:** 트레이너와 단일 약력을 같은 리비전으로 복원하고 공개 리비전의 소속·수동 순서·사진을 사용한다. 프로필과 소속 지점이 모두 공개일 때만 고객 화면과 사진의 공개 사용처에 포함한다. 이동·사진/약력/순서 수정 초안은 기존 공개본을 바꾸지 않으며 기존 미리보기·권한·CSRF·잠금·저장/공개/철회 경계를 재사용한다. [이번 자체 검사 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)는 독립 검증·운영 배포·사용자 승인을 대신하지 않는다.

### FR-07 팝업

**사용자 한정 확인:** 2026-10-11 사용자는 “게시글에 연결된 팝업을 관리자에서 기간별로 운영하고 실제 공개 화면까지 연결되는 흐름”을 직접 확인했다. 이 한정 확인을 소식 CMS 전체·경계 시간·차단·오늘 숨김·복수 팝업·실제 기기·한국어 IME·관리자 전체 사용성 승인으로 확대하지 않는다. 과거 검수/캡처 JSON의 승인 대기 상태는 촬영 당시 기록으로 보존한다.

- **소식 작성·편집 화면 안에 ‘팝업 설정’을 둔다.** 현재 글에 연결하며 URL을 수동 입력하지 않는다. 글당 사용 여부·시작·종료 일시 한 묶음을 관리한다. 신규 글은 먼저 초안 저장하도록 안내한다. 한국 시간(Asia/Seoul, UTC+09:00)을 입력창·안내에 명시한다.
- **‘팝업 설정 적용’은 본문 초안 저장·게시와 독립적이다.** 작성 중인 제목·본문 입력을 유지하고 글을 자동 저장·게시하지 않는다. 뒤이은 본문 저장·게시가 별도 적용한 팝업 설정을 되돌리지 않는다. 게시 권한·편집 잠금과 설정 버전 충돌 검사를 유지한다.
- 팝업 제목·문구·선택 사진과 연결 글은 **현재 공개 리비전의 제목·짧은 설명·대표 사진**을 사용한다. 수정 초안이 있어도 공개본을 유지한다. 별도 팝업용 문구·이미지 덮어쓰기는 이번 범위에 구현하지 않았다.
- 연결 글 공개 + 활성 상태 + 서버 시각 `시작 <= 현재 < 종료`가 표시 조건이다. 사용 설정 시 두 기간 값과 `시작 < 종료`를 검증한다. 홈 방문·갱신, 팝업 직접 URL과 모바일 데이터 요청에 같은 조건을 적용한다. 모바일 순차 노출은 각 알림 직전에 서버 판정을 다시 받는다. 프로토타입 원본의 브라우저 시각 검수와 구분한다.
- 사용 안 함·시작 전·노출 대상·기간 종료·게시글 비공개 상태와 이유를 보여준다. 기간 종료·팝업 중지는 글 공개 상태를 바꾸지 않는다. 글을 비공개로 하면 기간 안이어도 팝업에서 제외한다.
- **2026-10-10 사용자 결정:** 여러 글의 기간 중첩 허용, 개수 제한 없이 전체 자동 노출, 게시글 등록 시각이 빠른 순서, 전체 지점 공통. 등록 시각은 최초 초안 저장 리비전 시각으로 조회하고 같은 시각이면 글 ID 순으로 안정 정렬한다. 공개·수정 순서로 다시 정렬하지 않는다.
- **PC 768px 이상은 별도 창을 요청하고 모바일은 같은 페이지 레이어**를 사용한다. 브라우저가 새 탭으로 처리할 수 있다. 자동 차단 시 수동 진입이 가능하면 정상 대응이다.
- **PC 위치에 대한 최신 사용자 요청:** 같은 위치에 겹쳐 시작하지 않도록 화면 중앙 주변에서 랜덤하게 분산한다. `left/top` 시작 좌표에 작업 영역의 원점을 반영하고, 내용 크기 확정 후 실제 위치를 다시 보정한다. 창이 가장자리에 붙지 않도록 여백을 확보하며 작은 작업 영역에서는 크기와 분산 폭을 줄인다. 부분 겹침은 가능하고 노출 개수·순서는 바꾸지 않는다. 구체적인 초기 값은 [디자인 문서](../prototype/DESIGN.md#상태별-구현-기준), 실제 좌표와 브라우저 제한은 [위치 검수 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 기록한다.
- **최신 사용자 확정: 일반 닫기 후 새로고침·홈 재방문 때 다시 자동 표시한다.** 기존 ‘탭 세션당 한 번’ 제한을 폐기한다. 매 홈 로드에서 전체 대상을 등록 순서로 시도하고 PC는 글별 이름으로 열린 창을 재사용한다. 모바일은 한 레이어를 닫으면 다음 대상이 열린다. 같은 화면의 지점 탭·크기 변경만으로 추가 자동 노출하지 않는다. 열기·로딩 실패를 표시 완료로 기록하지 않는다.
- 사용자 요청으로 평소 **‘알림 보기’ 버튼을 제거한다.** 자동 차단·로딩 실패 시에만 해당 대상의 텍스트형 ‘직접 열기’ 복구 링크를 표시한다. 새로고침에서는 자동 열기를 다시 시도하고 여전히 실패하면 복구 링크를 남긴다. 세션 기록/세션 저장소의 제한은 자동 노출을 막지 않는다. JavaScript 실패 시 기본 링크로 같은 탭의 연결 공개 소식을 읽는다.
- ‘오늘 하루 보지 않기’를 선택해 닫았을 때만 해당 팝업을 한국 시간 다음 날 00:00까지 숨긴다. 일반 닫기는 숨김 기록을 저장하지 않는다. 숨김은 새로고침·재방문·새 탭에서도 유지하고 만료 후 다시 자동 노출한다. 저장에 실패하면 안내하며 성공한 것처럼 숨기지 않는다. 직접 URL은 숨김과 별개로 서버 공개·기간 조건을 적용한다. 닫기는 오늘 숨김과 비슷한 크기의 **‘닫기 ×’ 텍스트형**이다. [재노출 검증 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약).
- 복수 PC 창도 같은 기준 폭을 적용하고 내용에 맞는 높이로 표시한다. 긴 내용은 작업 영역 안에서 스크롤하고 크기 변경 제한에서도 하단 컨트롤을 본문에 붙인다. 수치·정적 원본과의 차이는 [디자인 문서](../prototype/DESIGN.md#상태별-구현-기준), 실제 창 경계 검증과 미실행 Whale 검사는 [크기 수정 기록 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에 구분한다.
- 모바일은 배경 스크롤·탐색을 막고 하단 문의 바를 숨긴다. 닫기·바깥 누르기·Escape, 짧은 화면의 내부 스크롤, 포커스·스크롤 복원을 제공한다.

## 5. 품질과 완료 판단

- PC·모바일 반응형에서 겹침·잘림·페이지 가로 넘침·하단 문의 바의 본문 가림이 없어야 한다. 지점 탭·링크·문의 대상·소식 분류가 일관되어야 한다.
- 키보드 포커스와 기본 탐색을 유지한다. JavaScript가 실패하면 모바일 메뉴 링크·핵심 본문·모든 지점 패널·주소·연락 정보가 남는다. 사진 실패는 중립 대체 표시, 선택 콘텐츠 0건은 숨김/빈 안내로 처리한다.
- 승인된 시설 슬라이드 외의 불필요한 애니메이션·장식을 추가하지 않는다. 동작 줄이기 설정은 자동 이동을 끄고 수동 탐색을 제공한다.
- 자동 브라우저 검사, 사용자 시각 승인, 서버·권한 검사, 실제 기기·외부 서비스·운영 검증을 분리해 보고한다. 상태별 PASS는 실제 CMS 보호나 제품 출시 완료가 아니다.
- 기존 검수 자료와 승인 범위는 [디자인 문서의 검수 기록](../prototype/DESIGN.md#검수-자료와-한계)에 있다. 이번 M1의 실제 서버·브라우저 검사와 새 캡처는 [별도 검수 기록](../backend/review/README.md)에 두며 기존 자료를 재생성하지 않았다.

## 6. 이후 진행과 미결정 사항

Django/Wagtail과 단계적 공개 정책은 기술 설계의 두 추천안에 대한 사용자 ‘ㅇㅇ’ 및 기존 최신 문서의 승인 기록을 근거로 유지한다. 이번에는 공식 호환성을 확인해 Python 3.13.15·Django 5.2.18·Wagtail 7.4.3·PostgreSQL 17.11로 소식 CMS를 로컬 실행했다. 정확한 버전·실행 파일·명령은 [백엔드 안내](../backend/README.md)에 있다.

소식·팝업 수정 후 M2-1 브랜드·홈 소개와 M2-2 지점·시설을 구현하고 R1 독립 재검증을 마쳤다. 첫 로컬 체크포인트 확보와 설계의 별도 지시를 받아 M2-3 트레이너 관리·실제 지점 상세 연결을 구현했다. 자체 검사와 독립 검증·사용자 시각/관리자 사용성 승인은 구분한다. 진행 근거와 현재 Git 상태는 [작업 흐름](WORKFLOW.md)을 따른다. 공개 디자인과 전체 제품 범위는 유지하며 과거 단계의 중지·미착수 문구는 당시 범위다.

| 미결정 / 미검토 항목 | 필요한 확인 |
| --- | --- |
| 실제 콘텐츠 | 공식 로고·소개·지점 수와 명칭·시설 사진·주소·운영시간·전화/카카오톡·트레이너 사진/약력. 현재 두 지점은 검토용 예시 |
| CMS 사용성 | 2026-10-11 게시글 연결 팝업의 기간 운영→공개 화면 연결을 한정 확인했고 브랜드·지점 관리자 UI와 저장→공개 흐름을 직접 확인·승인했다. 시설 사진 조작·경계 상태 전체, 소식·트레이너 관리자 전체 사용성과 오류/동시 저장 안내·이미지 입력 경험의 나머지 범위는 미확인 |

| 트레이너 후속 운영 규칙 | 공개 필수 이름·소속 지점, 나머지 선택, 단일 약력 목록·지점 내 수동 표시 순서는 FR-03에 확정 반영. 프로필 삭제/복원·운영 계정 확대는 M2-3 범위 밖이며 미결정 |

| 지도 | 카카오맵·페이지 내 지도+외부 링크는 확정·로컬 구현·테스트 주소 두 곳의 실제 SDK 자체 검수 완료. 초기403은 보존. 독립 검증·F01 보완 재확인 완료. 실제 지점 주소·위치 확인·시각/실제 기기 검증은 남음 |
| 후속 기술 구현 | 트레이너 모델·공개 경계는 M2-3 로컬 구현, 초기 독립 FAIL → R1 보완 → 독립 재검증 PASS_WITH_WARNINGS. 홈 최근 소식 연결은 M2-4 로컬 구현·독립 검증 PASS_WITH_WARNINGS·특정 5건 배치 승인 완료이며 운영 저장소/캐시는 미구현. 로컬 DB/미디어 검증을 배포 검증으로 확대하지 않음 |
| 배포·운영 | 호스팅·예산·도메인·운영 책임·업로드 저장소·백업/복구・배포/롤백 |
| 최종 검수 | 실제 콘텐츠 교체, 실제 기기·다른 브라우저·문의/지도 연동·관리자·운영 검증 |

**M2-3 종료 상태:** 개발 자체 검사와 독립 재검증은 각각의 보고 근거로 구분하며 최종 독립 판정은 PASS_WITH_WARNINGS다. 직급/약력 배치만 사용자 승인 범위이며 관리자 사용성·실제 기기/Whale/한국어 IME·운영 환경은 미검증이다. 첫 체크포인트 `46ef337` push 이후 M2-3·R1/종료 문서는 설계 검토와 Git 담당 반영을 거쳐 `b517cc209f0f3ac66d7b602450cf5d9dca16d58c`으로 main → origin/main push 완료했다. 이는 설계가 전달한 Git 결과이며 개발에서 Git 쓰기·인증/영구 설정 변경을 수행하지 않았다. 이 종료 문서 작성 시점의 M2-4 변경은 미커밋이며 이후 Git 반영 결과와 구분한다. 당시 [종료 문서 검사 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)는 제품 테스트를 재실행하지 않았으며 M2-4 자체 검수는 새 기록이다.

**M2-4 종료:** 독립 검사 결과는 [원 보고서 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)를 읽은 것이며 이번 [종료 문서·보존 검사 · 정리됨](../backend/review/README.md#정리-후-유지한-검증-요약)에서는 제품 테스트/캡처를 재실행하지 않았다. 초기 자체/독립 FAIL·검수 JSON·승인 대기 표시는 촬영 당시 기록으로 보존하고 위 후속 사용자 승인을 별도로 기록한다. Git b517cc2 push 완료와 종료 문서 작성 시점의 M2-4 미커밋 상태를 구분하며 미확정 운영·자료·지도/연락처·배포는 그대로 남긴다. 이후 기술/운영 구체화나 새 기능은 시작하지 않는다.

## 7. 이전 요구와 현재 결정의 차이

| 이전 참고 자료 | 현재 기준 / 확정 근거 |
| --- | --- |
| 특정 사이트 레퍼런스·복수 폰트·과거 색상·스크롤 등장 효과 | 사용자가 선택하고 실제 검토한 A 방향·Pretendard·중립색/절제된 파랑을 사용. 과거 스타일을 승계하지 않음 |
| 한 지점 기본 예시·홈의 병렬 지점 정보 | 사용자 요청으로 본점 포함 두 지점을 기본 예시로 하고, 데이터 기반 탭에서 선택 지점만 표시 |
| 홈 트레이너·위치, 트레이너 독립 메뉴 | 지점 안내 별도 페이지에 소속 정보와 상세를 모음. 사용자 요청과 ‘ㅇㅋ 이대로 가자’ 기준 |
| 홈의 별도 지점/시설 구역, 수동 슬라이드 버튼 | 지점·시설 통합, 홈/상세 동일한 버튼 없는 자동 슬라이드. ‘시설슬라이드 통과’와 홈 적용 확인 |
| 여백 많은 소식 목록·상세 하단 두 버튼 | 촘촘한 목록과 두 하단 링크 제거. ‘글 목록 통과’ 및 수정 요청 반영 |
| 모든 기기의 별도 창 팝업 | PC 별도 창 / 모바일 레이어. 사용자 ‘팝업창은 일단 이정도면 될 것 같음’ 기준 |
| 소개·지점·트레이너 저장 즉시 공개 | 전체 초안·미리보기·공개로 통일하는 안을 선택 |
| Google 지도, 본점/삭제/복원 등의 과거 운영 정책 | 과거 정책 자체는 승계하지 않음. 이번 사용자 답변으로 본점 1곳·공개 본점 우선/새 방문 기본값·미완성 초안/공개 필수값·마지막 공개 지점 철회를 FR-02에 확정 반영. 지도는 2026-10-11 카카오맵·페이지 내 지도+외부 링크로 별도 확정. 본점 교체·삭제/복원 절차는 미결정 |
| 과거 백엔드·DB·테스트·실행 경로 | 현재 구현의 근거로 사용하지 않음. 이번에 새로 구현·검증한 `backend/`와 보존한 프로토타입을 현재 상태의 근거로 삼음 |

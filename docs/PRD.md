# Y3GYM 제품 요구사항

갱신일: 2026-10-10. 이 문서는 현재 프로젝트의 제품 기준이다. 사용자 확정 결정과 실제 저장소를 대조했으며, 과거 참고 자료인 [PRD.previous.md](legacy/PRD.previous.md)를 복사하거나 그 운영 정책 전체를 승계하지 않았다.

디자인의 수치·화면·승인 근거는 [현재 디자인 문서](../prototype/DESIGN.md), CMS 입력 구조와 기술 제안은 [콘텐츠 관리·기술 설계](IMPLEMENTATION-PLAN.md), 실행·현재 상태는 [루트 README](../README.md)를 따른다. 최신 사용자 지시가 문서와 다르면 이유와 적용 범위를 기록해 갱신한다.

## 1. 목적과 사용자

브랜드·지점·시설·트레이너를 소개하고 방문자를 선택 지점의 전화·카카오톡 문의로 연결하는 공식 홈페이지를 만든다. 운영자는 개발자 도움 없이 고정된 화면의 콘텐츠를 관리한다. PT 운영관리 제품과 분리한다.

| 사용자 | 주요 동선 |
| --- | --- |
| 처음 방문한 고객 | 홈 소개·선택 지점 시설 → 별도 지점 안내 → 이용안내·위치 → 해당 지점 문의 |
| 트레이너를 살펴보는 고객 | 지점 안내 → 지점 탭 → 소속 트레이너·약력 → 같은 지점 문의 |
| 소식을 확인하는 고객 | 홈 최근 소식 / 소식 메뉴 / 팝업 → 공통 소식 상세 |
| 콘텐츠 운영자 | 관리자 로그인 → 콘텐츠 편집 → 초안 저장 → 미리보기 → 명시적 공개 |
| 시스템 관리자 | 운영 계정·권한·운영 환경 관리. 구체적인 역할 분리는 후속 설계 대상 |

고객 회원가입·로그인은 제공하지 않는다. 방문자·매출·전환율의 수치 목표나 분석 도구는 확정하지 않았다.

## 2. 제품 범위와 현재 상태

**제품에 포함:** 브랜드 소개, 다지점, 지점별 시설·이용안내·트레이너·위치·문의, 공통 공지·이벤트, 소식 연결 팝업, 운영자 콘텐츠·이미지 관리.

**범위 밖:** 가격·요금표·결제·회원권 판매, PT 연계·예약·출결·고객 계정, 자체 상담 접수 폼·고객정보 수집, 지점별 게시판·댓글·좋아요·태그·소셜 기능, 자유 페이지 빌더·섹션 자유 재배치, 별도 관리자 프런트 서비스, 예약 발행·다단계 승인. 별도 요청 없이 이러한 기능을 추가하지 않는다.

| 구분 | 2026-10-10 확인 상태 |
| --- | --- |
| 공개 화면 | A 방향 디자인 검토 완료. 정적 홈·별도 지점 안내·소식·팝업·상태별 화면 존재 |
| 검수 자료 | 기존 `prototype/review/` 보존. 이번 실제 소식 CMS 검증·캡처는 `backend/review/`에 분리 |
| 기술 선택 | Django/Wagtail + PostgreSQL, 콘텐츠 초안·미리보기·공개 방식 선택 |
| 실제 CMS·DB | 소식·팝업에 이어 M2-1 브랜드·홈 소개 관리와 공개 홈 연결 구현. 별도 로컬 PostgreSQL·리비전·보호된 미디어 사용. M2-2 지점·시설과 실제 지점 안내·홈 연결 구현. M2-3 트레이너 관리·실제 지점 상세 연결 구현. [초기 독립 FAIL](../backend/review/trainers-independent/README.md)의 관리자 최신 초안 검색을 [R1](../backend/review/trainers-repair/README.md)에서 보완한 뒤 [독립 재검증 PASS_WITH_WARNINGS](../backend/review/trainers-independent-recheck/README.md). F01/P2·W02~W04 해결·새 차단 결함 없음, W01 기존 포맷 경고 유지 |
| 게시글 연동 팝업 | 글 편집 화면에서 사용·기간 별도 적용, 실제 DB·공개 홈 연결. 복수 중첩 전체 자동 노출·등록 순서·전 지점 공통. [실제 검수](../backend/review/popups/README.md) |
| 지도·문의 | 예시 영역·안내만 구현. 실제 지도·전화·카카오톡 연결 없음 |
| 운영 준비 | 실제 자료·호스팅·저장소·도메인·백업·배포 미확정/미구현 |

문서 정리 시에는 과거 CMS 구현 기록과 실제 파일이 일치하지 않아 계획으로 정정했다. 이후 이번 M1에서 새로 구현한 [백엔드 소스·실행 안내](../backend/README.md)와 [실제 검수 기록](../backend/review/README.md)을 현재 상태의 근거로 삼는다. 과거 기록을 완료 근거로 승계하지 않는다.

## 4. 기능 요구사항

### FR-01 브랜드와 공통 콘텐츠

- 브랜드명·로고·대표 사진·소개 제목·설명을 관리한다. 레이아웃·메뉴·색상을 자유 편집하는 페이지 빌더를 만들지 않는다.
- **M2-1:** 사이트 공통 한 묶음으로 브랜드명·선택 로고·소개 제목/설명·선택 대표 사진/대체 설명/사진 중심을 관리한다. 초안 → 권한 있는 홈 미리보기 → 명시적 공개·철회. 공개 홈·실제 소식/팝업의 공통 브랜드 표시는 현재 공개 리비전만 사용한다. M2-2에서 실제 지점 안내·홈의 지점/시설도 현재 공개 리비전으로 연결했다. 정적 원본은 보존한다.
- **이번 사용자 확인:** 공개 시 브랜드명·소개 제목만 필수이며 공백만 입력한 값은 허용하지 않는다. 설명·로고·대표 사진은 선택이다. 미완성 초안 저장은 허용한다. 로고가 없으면 텍스트 브랜드명, 대표 사진이 없으면 기존 텍스트 중심 배치를 사용한다. 공개본이 없으면 준비 중 안내와 기본 지점·소식 탐색을 남긴다.
- 홈의 지점·시설·최근 글은 원본 지점·소식 데이터에서 구성한다. 같은 콘텐츠를 홈용으로 중복 등록하지 않는다.
- 실제 자료가 없으면 임시 텍스트 로고·가상 사진·예시 운영 정보로 검토하며 임시 자료 표시를 제공한다. 확인되지 않은 경력·자격·실적·가격·행사 혜택을 만들지 않는다.

### FR-02 지점·시설

- 본점과 추가 지점은 동일한 콘텐츠 구조를 사용한다. **현재와 이후 기본 예시는 본점·예시점 두 개**다. 예시점은 실제 등록 지점이 아니다.
- 지점명·소개·시설 사진·주소·운영시간 등 이용안내·연락수단·소속 트레이너를 지점에 묶는다. 초안 저장 → 미리보기 → 명시적 공개·철회와 표시 순서를 관리한다. 본점은 안정적인 `main` 식별자의 1곳이며 공개 상태이면 항상 첫 순서·새 방문 기본값이다. 명시한 URL·같은 탭의 선택이 우선하고 본점 비공개 시 첫 유효 공개 지점을 선택한다. 추가 지점은 공개본의 표시 순서와 안정적인 ID 순이다. 본점 교체·지점 삭제/복원 절차는 이번 범위에 포함하지 않는다.
- 홈과 지점 안내의 탭·패널은 지점 목록에 따라 늘어난다. 한 번에 선택 지점만 보여주며, 많은 탭은 탭 줄 안에서 가로 스크롤한다.
- 지점 선택은 URL·같은 탭의 저장 상태와 연결 동선에서 유지한다. 최초 기본 선택은 현재 예시의 첫 지점이며 선택한 이름을 표시한다. 삭제·알 수 없는 지점 ID는 현재 화면에서 유효한 첫 지점으로 복구하지만 실제 문의 대상은 명시해야 한다.
- 시설은 사진·제목·설명·대체 설명·순서를 가진다. 홈과 상세에 같은 원본·같은 자동 슬라이드를 사용한다. 자동 이동·반응형·접근성 상세는 디자인 문서를 따른다.
- **M2-2 구현:** `Branch`와 `FacilityImage`를 한 편집·리비전 단위로 관리하고 실제 `/`·`/branches/`에 공개본을 연결한다. 신규 지점은 안정적인 식별자를 자동 생성하며 홈·지점·소식·팝업의 선택 목록도 현재 공개 지점만 사용한다. 기존 `branch-data.js`·생성 HTML·검수 자료는 정적 이력으로 보존한다.
- 미완성 초안 저장을 허용한다. 공개 시 **지점명·주소·운영시간만 필수**이며 공백을 거부한다. 소개·사진·트레이너·연락처는 선택이다. 이미지 없는 시설 항목은 안내 후 초안에 보관하고 공개 사진에서 제외한다. 사진·트레이너 0건과 없는 연락수단의 영역·버튼은 숨긴다. M2-2 당시에는 트레이너 CMS를 제외했다. 이후 M2-3에서 승인된 가상 A/B 자료를 임시 표시와 함께 연결했다.
- 마지막 공개 지점도 철회할 수 있다. 0곳이면 지점 준비 중 안내와 브랜드·소식 탐색을 남기고 공통·모바일 문의 버튼을 모두 숨긴다. 원본 지점을 삭제하지 않는다. 연락처가 있는 선택 지점의 해당 채널만 모의 안내로 제공하고 실제 전화·카카오톡·지도는 연결하지 않는다.

### FR-03 트레이너

- 트레이너는 한 지점에 소속되며 **지점 안내에서만** 소개한다. CMS와 실제 지점 상세 연결은 **M2-3 로컬 구현**이며 범위·완료 기준은 [구현 계획](IMPLEMENTATION-PLAN.md#다음-단위-m2-3-트레이너-관리), 실제 자체 검사·새 캡처·보존과 한계는 [트레이너 검수](../backend/review/trainers/README.md)에 둔다. [초기 독립 검증 FAIL](../backend/review/trainers-independent/README.md)의 최신 초안 검색 불일치를 [M2-3-R1](../backend/review/trainers-repair/README.md)에서 보완했다. 이후 [독립 재검증 PASS_WITH_WARNINGS](../backend/review/trainers-independent-recheck/README.md)로 F01/P2·W02~W04 해결·새 차단 결함 없음을 확인했다. W01 기존 포맷 경고는 유지하며 관리자 사용성 승인은 별개다. **2026-10-10 사용자 시각 승인:** 검토한 [PC](../backend/review/trainers/regressions-final/combined/trainer/short-biography-desktop-section.png)·[모바일](../backend/review/trainers/regressions-final/combined/trainer/short-biography-mobile-section.png)의 직급·약력 배치를 “이 배치로 유지”로 확정했다. 이 선택정보 배치 승인과 관리자 사용성·실제 기기·배포 승인은 별개다.
- **사용자 확정:** 공개 시 **이름·소속 지점만 필수**다. 사진·한줄 소개·직급·약력은 선택이며 미완성 초안 저장을 허용한다. 비어 있는 선택 영역은 고객 화면에서 숨긴다.
- **약력은 항목을 나열하는 단일 목록**으로 관리한다. 경력·자격·수상 등으로 분류하지 않는다. **같은 지점의 트레이너 표시 순서는 CMS에서 수동 지정**한다.
- 관리자 목록의 이름·소속과 검색의 이름·소개는 최신 초안 기준이다. 검색은 최신 리비전이 없을 때만 현재 모델 값을 사용하며 최신 초안의 빈 값으로 이전 공개 값을 검색하지 않는다. 소속 필터·검색·공개 상태 필터·페이지 이동을 함께 유지한다.
- 프로필과 약력은 한 편집·리비전 단위다. 지점에서 소속 트레이너 관리로 진입하며 지점·시설과 별도 저장 단위임을 명시한다. 초안 저장 → 권한 있는 미리보기 → 명시적 공개·철회를 따른다.
- **공개 프로필과 공개 소속 지점 조건을 함께 적용**하여 선택 지점의 프로필만 표시한다. 지점이 비공개가 되어도 원본 프로필을 삭제하거나 자체 공개 설정을 임의 변경하지 않는다. 지점 이동은 프로필을 복제하지 않고 소속을 변경하며, **소속 이동 초안은 현재 공개 소속에 영향을 주지 않는다.** 명시적 공개 후 새 소속에만 반영한다.
- 사진은 [디자인 문서](../prototype/DESIGN.md#글자와-사진)의 **4:5**와 기존 승인 카드 배치를 따른다. 현재 정적 화면은 가상 인물과 짧은 소개만 제공한다. 실제 자료가 없으면 기존 가상 자료에 임시 자료 표시를 붙여 로컬 검토에 사용할 수 있으며 확인되지 않은 경력·자격·실적을 만들어 넣지 않는다.

### FR-04 위치와 문의

- 주소·운영시간·위치·전화·카카오톡은 선택 지점의 별도 안내 페이지에 둔다. 홈 공통 CTA와 모바일 하단 문의 바도 선택 지점의 문의 구역으로 연결한다.
- 문의 대상 지점명을 보여주며 공통 문의를 설명 없이 본점 번호로 연결하지 않는다. 실제 전화는 읽고 복사할 수 있는 번호와 연결 버튼을 제공하고, 없는 채널은 숨기는 방향을 유지한다.
- 실제 지도 제공자·입력·외부 연결 방식은 미결정이다. 이전 프로젝트의 Google 퍼가기 선택을 자동 승계하지 않는다. 지도 실패·미등록·JavaScript 실패에도 주소·기본 연락 정보는 남아야 한다.
- 현재 전화·카카오톡은 모의 안내만 제공하고, 지도는 배치 예시다. 실서비스 연동 완료로 취급하지 않는다.

### FR-05 공통 소식

- 공지·이벤트는 브랜드 공통 콘텐츠이며 지점 소유권을 붙이지 않는다. 제목·분류·짧은 설명·선택 대표 이미지·본문을 관리한다.
- 목록은 전체·공지·이벤트 분류와 구분선 행을 사용한다. 승인된 촘촘한 밀도를 유지하고 긴 제목·설명은 줄바꿈한다. 빈 목록에는 안내·분류·기본 탐색을 제공한다.
- 상세 하단의 **‘지점 위치와 문의 보기’, ‘목록으로 돌아가기’는 제거**한다. 현재 위치의 ‘소식’ 링크와 공통 메뉴는 유지한다. 분류·목록 페이지·선택 지점의 맥락을 연결 동선에서 유지한다.
- 글쓰기는 한 본문에서 문단을 이어 쓰는 익숙한 편집 방식으로 설계한다. 한글·문단·서식·링크·본문 이미지 삽입/교체와 대표 이미지 구분을 실제 CMS에서 검증해야 한다.
- **2026-10-10 사용자 확정:** 홈 최근 소식은 **최대 5건**이다. **홈과 소식 목록은 최초 공개 최신순**이며 수정·재공개로 순위를 올리지 않는다. **팝업은 기존 최초 등록 빠른순**을 유지한다. 홈의 실제 공개 글 연결은 [M2-4 후속 계획](IMPLEMENTATION-PLAN.md#다음-미완료-단위-m2-4-홈-최근-소식-실제-공개-글-연결)만 기록했고 명시적 다음 구현 지시 전 **미착수**다.
- 목록 페이지당 10건·정적 홈 최근 최대 3건은 보존한 프로토타입의 초기 표시값이다. 새 홈 최대 5건 결정과 구분하며 목록 페이지당 10건의 운영 확정·공개일 편집·삭제/복원·운영 권한은 이번에 확정하지 않는다.
- **M1 구현 상태:** 실제 소식 CMS와 `/news/`, `/news/<숫자 ID>/`의 공개 목록·상세를 구현했다. 승인된 CSS·글꼴·촘촘한 행 구조를 그대로 사용한다. 홈 최근 글은 정적 예시다. 팝업은 후속 M1 작업에서 실제 공개 글과 연결했으며 M2-2에서는 공통 지점 선택을 실제 공개 지점 목록으로 통일했다.

### FR-06 공개 흐름과 미디어

- **브랜드·지점/시설·트레이너·소식 모두 초안 저장 → 미리보기 → 명시적 공개**로 통일하기로 결정했다. 이전의 소개·지점·트레이너 저장 즉시 반영 정책은 채택하지 않는다.
- 새 초안은 고객 화면에 노출하지 않는다. 공개 콘텐츠를 수정 초안으로 저장해도 기존 공개 제목·본문·사진·날짜를 유지한다. 미리보기는 권한 있는 운영자에게 수정본을 보여주고 일반 고객 URL은 공개본만 제공한다.
- 공개 철회 시 관련 공개 목록·상세·연결 팝업에서 제외한다. 팝업의 사용 여부·기간 조작은 콘텐츠 공개와 구분하며 구체적인 CMS 조작은 미검토다.
- 초안 이미지·원본·관리자 썸네일의 무권한 접근을 차단한다. 공개 파일 덮어쓰기 대신 새 파일 참조로 교체하고 현재 공개 사용처를 기준으로 제공한다. 마지막 공개 사용처 철회 후 새 무권한 요청을 차단하는 경계를 검증해야 한다.
- **M1에서는 소식에 한해** 공개 리비전 분리·권한 있는 미리보기·이미지 직접 접근 통제·파일 덮어쓰기 방지·오래된 화면 및 실제 동시 저장 충돌을 구현하고 검증한다. 브랜드·지점·트레이너·팝업, 최종 운영 권한·삭제/복원·배포 캐시 정책까지 완료한 것은 아니다. 수행 결과와 한계는 [M1 검수 기록](../backend/review/README.md)을 따른다.
- M2-1은 같은 공개본·미디어·저장 충돌 경계를 브랜드·홈 소개에 적용한다. 브랜드와 소식의 공유 이미지 사용처도 함께 판정한다. 전체 지점/트레이너 공개 통제·최종 운영 권한·삭제/복원 정책까지 완료한 것은 아니다. [브랜드 검수 기록](../backend/review/brand-home/README.md)에서 이번 실행과 기존 검사를 구분한다.

- **M2-2:** 지점과 시설 자식 목록을 같은 공개 리비전에서 복원한다. 주소·순서·시설 추가/삭제/재정렬·사진 변경의 초안이 공개본에 새지 않는다. 지점 시설의 공개 이미지 사용처를 소식·브랜드와 합쳐 마지막 공개 사용처 철회 후 익명 변환본 요청을 차단한다. 미리보기 권한·`private, no-store`, CSRF·모델 권한·잠금·오래된 폼/동시 저장 경계는 기존 패턴을 재사용한다. 로컬 자체 검수와 한계는 [지점 검수 기록](../backend/review/branches/README.md)에 둔다.

M2-2는 [초기 독립 검증 FAIL](../backend/review/branches-independent/README.md) → [R1 보완](../backend/review/branches-repair/README.md) → [독립 재검증 PASS_WITH_WARNINGS](../backend/review/branches-independent-recheck/README.md)로 종료 상태를 갱신한다. 지점·브랜드·소식의 실제 행 잠금으로 양쪽 교차 순서의 초안 저장/공개·철회, 최신 리비전·본문/시설 보존과 권한/CSRF/hooks를 독립 재실행해 F01·F02·W01 해결·차단 결함 없음을 확인했다. 기존 `backend/review/workflow-01/verify.py` 전역 포맷 경고와 실제 기기·Whale·한국어 IME·운영 환경·사용자 시각/관리자 사용성 미검증은 남는다. 이전 보고·캡처는 당시 기록으로 보존하며 M2-2 종료 문서 작업에서는 제품 검사를 재실행하지 않았다.

- **M2-3:** 트레이너와 단일 약력을 같은 리비전으로 복원하고 공개 리비전의 소속·수동 순서·사진을 사용한다. 프로필과 소속 지점이 모두 공개일 때만 고객 화면과 사진의 공개 사용처에 포함한다. 이동·사진/약력/순서 수정 초안은 기존 공개본을 바꾸지 않으며 기존 미리보기·권한·CSRF·잠금·저장/공개/철회 경계를 재사용한다. [이번 자체 검사](../backend/review/trainers/README.md)는 독립 검증·운영 배포·사용자 승인을 대신하지 않는다.

### FR-07 팝업

- **소식 작성·편집 화면 안에 ‘팝업 설정’을 둔다.** 현재 글에 연결하며 URL을 수동 입력하지 않는다. 글당 사용 여부·시작·종료 일시 한 묶음을 관리한다. 신규 글은 먼저 초안 저장하도록 안내한다. 한국 시간(Asia/Seoul, UTC+09:00)을 입력창·안내에 명시한다.
- **‘팝업 설정 적용’은 본문 초안 저장·게시와 독립적이다.** 작성 중인 제목·본문 입력을 유지하고 글을 자동 저장·게시하지 않는다. 뒤이은 본문 저장·게시가 별도 적용한 팝업 설정을 되돌리지 않는다. 게시 권한·편집 잠금과 설정 버전 충돌 검사를 유지한다.
- 팝업 제목·문구·선택 사진과 연결 글은 **현재 공개 리비전의 제목·짧은 설명·대표 사진**을 사용한다. 수정 초안이 있어도 공개본을 유지한다. 별도 팝업용 문구·이미지 덮어쓰기는 이번 범위에 구현하지 않았다.
- 연결 글 공개 + 활성 상태 + 서버 시각 `시작 <= 현재 < 종료`가 표시 조건이다. 사용 설정 시 두 기간 값과 `시작 < 종료`를 검증한다. 홈 방문·갱신, 팝업 직접 URL과 모바일 데이터 요청에 같은 조건을 적용한다. 모바일 순차 노출은 각 알림 직전에 서버 판정을 다시 받는다. 프로토타입 원본의 브라우저 시각 검수와 구분한다.
- 사용 안 함·시작 전·노출 대상·기간 종료·게시글 비공개 상태와 이유를 보여준다. 기간 종료·팝업 중지는 글 공개 상태를 바꾸지 않는다. 글을 비공개로 하면 기간 안이어도 팝업에서 제외한다.
- **2026-10-10 사용자 결정:** 여러 글의 기간 중첩 허용, 개수 제한 없이 전체 자동 노출, 게시글 등록 시각이 빠른 순서, 전체 지점 공통. 등록 시각은 최초 초안 저장 리비전 시각으로 조회하고 같은 시각이면 글 ID 순으로 안정 정렬한다. 공개·수정 순서로 다시 정렬하지 않는다.
- **PC 768px 이상은 별도 창을 요청하고 모바일은 같은 페이지 레이어**를 사용한다. 브라우저가 새 탭으로 처리할 수 있다. 자동 차단 시 수동 진입이 가능하면 정상 대응이다.
- **PC 위치에 대한 최신 사용자 요청:** 같은 위치에 겹쳐 시작하지 않도록 화면 중앙 주변에서 랜덤하게 분산한다. `left/top` 시작 좌표에 작업 영역의 원점을 반영하고, 내용 크기 확정 후 실제 위치를 다시 보정한다. 창이 가장자리에 붙지 않도록 여백을 확보하며 작은 작업 영역에서는 크기와 분산 폭을 줄인다. 부분 겹침은 가능하고 노출 개수·순서는 바꾸지 않는다. 구체적인 초기 값은 [디자인 문서](../prototype/DESIGN.md#상태별-구현-기준), 실제 좌표와 브라우저 제한은 [위치 검수](../backend/review/popup-position/README.md)에 기록한다.
- **최신 사용자 확정: 일반 닫기 후 새로고침·홈 재방문 때 다시 자동 표시한다.** 기존 ‘탭 세션당 한 번’ 제한을 폐기한다. 매 홈 로드에서 전체 대상을 등록 순서로 시도하고 PC는 글별 이름으로 열린 창을 재사용한다. 모바일은 한 레이어를 닫으면 다음 대상이 열린다. 같은 화면의 지점 탭·크기 변경만으로 추가 자동 노출하지 않는다. 열기·로딩 실패를 표시 완료로 기록하지 않는다.
- 사용자 요청으로 평소 **‘알림 보기’ 버튼을 제거한다.** 자동 차단·로딩 실패 시에만 해당 대상의 텍스트형 ‘직접 열기’ 복구 링크를 표시한다. 새로고침에서는 자동 열기를 다시 시도하고 여전히 실패하면 복구 링크를 남긴다. 세션 기록/세션 저장소의 제한은 자동 노출을 막지 않는다. JavaScript 실패 시 기본 링크로 같은 탭의 연결 공개 소식을 읽는다.
- ‘오늘 하루 보지 않기’를 선택해 닫았을 때만 해당 팝업을 한국 시간 다음 날 00:00까지 숨긴다. 일반 닫기는 숨김 기록을 저장하지 않는다. 숨김은 새로고침·재방문·새 탭에서도 유지하고 만료 후 다시 자동 노출한다. 저장에 실패하면 안내하며 성공한 것처럼 숨기지 않는다. 직접 URL은 숨김과 별개로 서버 공개·기간 조건을 적용한다. 닫기는 오늘 숨김과 비슷한 크기의 **‘닫기 ×’ 텍스트형**이다. [재노출 검증](../backend/review/popup-revisit/README.md).
- 복수 PC 창도 같은 기준 폭을 적용하고 내용에 맞는 높이로 표시한다. 긴 내용은 작업 영역 안에서 스크롤하고 크기 변경 제한에서도 하단 컨트롤을 본문에 붙인다. 수치·정적 원본과의 차이는 [디자인 문서](../prototype/DESIGN.md#상태별-구현-기준), 실제 창 경계 검증과 미실행 Whale 검사는 [크기 수정 기록](../backend/review/popup-sizing/README.md)에 구분한다.
- 모바일은 배경 스크롤·탐색을 막고 하단 문의 바를 숨긴다. 닫기·바깥 누르기·Escape, 짧은 화면의 내부 스크롤, 포커스·스크롤 복원을 제공한다.

## 5. 품질과 완료 판단

- PC·모바일 반응형에서 겹침·잘림·페이지 가로 넘침·하단 문의 바의 본문 가림이 없어야 한다. 지점 탭·링크·문의 대상·소식 분류가 일관되어야 한다.
- 키보드 포커스와 기본 탐색을 유지한다. JavaScript가 실패하면 모바일 메뉴 링크·핵심 본문·모든 지점 패널·주소·연락 정보가 남는다. 사진 실패는 중립 대체 표시, 선택 콘텐츠 0건은 숨김/빈 안내로 처리한다.
- 승인된 시설 슬라이드 외의 불필요한 애니메이션·장식을 추가하지 않는다. 동작 줄이기 설정은 자동 이동을 끄고 수동 탐색을 제공한다.
- 자동 브라우저 검사, 사용자 시각 승인, 서버·권한 검사, 실제 기기·외부 서비스·운영 검증을 분리해 보고한다. 상태별 PASS는 실제 CMS 보호나 제품 출시 완료가 아니다.
- 기존 검수 자료와 승인 범위는 [디자인 문서의 검수 기록](../prototype/DESIGN.md#검수-자료와-한계)에 있다. 이번 M1의 실제 서버·브라우저 검사와 새 캡처는 [별도 검수 기록](../backend/review/README.md)에 두며 기존 자료를 재생성하지 않았다.

## 6. 이후 진행과 미결정 사항

Django/Wagtail과 단계적 공개 정책은 기술 설계의 두 추천안에 대한 사용자 ‘ㅇㅇ’ 및 기존 최신 문서의 승인 기록을 근거로 유지한다. 이번에는 공식 호환성을 확인해 Python 3.13.15·Django 5.2.18·Wagtail 7.4.3·PostgreSQL 17.11로 소식 CMS를 로컬 실행했다. 정확한 버전·실행 파일·명령은 [백엔드 안내](../backend/README.md)에 있다.

소식·팝업 수정 후 M2-1 브랜드·홈 소개와 M2-2 지점·시설을 구현하고 R1 독립 재검증을 마쳤다. 첫 로컬 체크포인트 확보와 설계의 별도 지시를 받아 M2-3 트레이너 관리·실제 지점 상세 연결을 구현했다. 자체 검사와 독립 검증·사용자 시각/관리자 사용성 승인은 구분한다. 진행 근거와 현재 Git 상태는 [작업 흐름](WORKFLOW.md)을 따른다. 공개 디자인과 전체 제품 범위는 유지하며 과거 단계의 중지·미착수 문구는 당시 범위다.

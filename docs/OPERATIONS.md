# Y3GYM 운영 배치 제안 — OPS-02

기준일: **2026-10-14**. 상태: **문서 제안 완료·사용자 선택 대기**. 계정·인프라·배포 방식·백업 정책은 아직 선택하거나 구현하지 않았다. 이 문서는 [구현 계획](IMPLEMENTATION-PLAN.md)의 OPS-01 이후 운영 검토 자료이며 [현재 환경 계약](../backend/README.md#개발과-운영-설정--ops-01)을 대체하지 않는다.

## 1. 확정 조건과 추천 범위

사용자는 사용할 기존 서버가 없고, 무료로 시작하며, 패치·장애 대응·백업 복구를 직접 맡고, 도메인을 보유한다고 답했다. 같은 질문을 다시 확인할 필요는 없다. 실제 도메인명·계정 소유·DNS 변경 권한은 DNS 준비 단계에서 확인하며 비밀값을 문서나 대화로 받지 않는다.

| 안 | 판단과 사용자에게 미치는 영향 |
| --- | --- |
| **A: OCI Always Free 단일 Linux VM** | **조건부 추천·미선택.** 기존 PostgreSQL과 private 파일 저장을 유지할 수 있다. 무료 용량 확보·회수·단일 서버 장애·사용자 직접 운영에 따른 중단과 복구 지연을 받아들이는 조건이다. |
| B: Render 무료 관리형 조합 | 이번 지속 운영 후보에서 보류한다. 무료 웹 서비스의 유휴 15분 후 중지·임시 파일시스템과 무료 PostgreSQL의 30일 만료가 현재 DB·이미지의 지속 보관 요구와 맞지 않는다. 이는 Render의 해당 무료 구성에 대한 판단이다. [Render 무료 서비스 조건](https://render.com/docs/free). |

무료 조건을 수용하기 어렵거나 안정적 운영·복구 보장을 우선하면 **유료 예산을 먼저 정하고 관리형 서비스를 다시 비교**한다. 이번 문서에서는 대체 제공자·지역·스택을 추가하지 않는다.

## 4. 접속·프록시·이미지 경계

- 공개 포트는 80/443, SSH는 사용자 IP로 제한한다. PostgreSQL은 loopback/Unix socket, Gunicorn도 loopback/Unix socket으로 제한한다. 마이그레이션 권한과 일상 앱 DB 권한을 나눈다.
- 실제 도메인의 DNS·TLS·허용 host·관리자 HTTPS 원점·CSRF 설정은 선택 후 정한다. ACME 자동 갱신은 제안이며 인증서를 발급하지 않았다.
- Nginx가 외부 `X-Forwarded-Proto`를 제거하고 실제 접속 scheme으로 설정하며 Gunicorn 직접 접근을 막은 뒤에만 `Y3GYM_TRUST_PROXY_HTTPS=1`을 적용한다. 프록시 신뢰의 전제는 [Django SECURE_PROXY_SSL_HEADER](https://docs.djangoproject.com/en/5.2/ref/settings/#secure-proxy-ssl-header)를 따른다.
- Nginx는 수집된 static만 제공한다. **`/media` alias·공개 버킷은 만들지 않는다.** 기존 [protected_media](../backend/news/views.py)와 [PrivateImageStorage](../backend/news/storage.py)를 그대로 유지한다. 익명 원본 차단, 공개 이미지의 허용 파생본만 익명 접근, 관리자 권한 확인을 우회하지 않는다. [본문 확대 이미지](../backend/news/content_images.py)도 같은 보호 경로를 사용한다. 새 원격 저장소 어댑터를 도입하지 않는다.
- secret·운영 DB·private media·백업은 코드 배포물과 분리한다. 비밀값을 저장소·로그·배포 manifest에 넣지 않는다.

## 5. 배포·롤백 초안

아래 경로는 **배치 초안이며 실제 디렉터리 존재·설정을 확인한 것이 아니다.** 릴리스마다 `releases/<release-id>/backend`와 형제 `prototype`을 함께 두고 venv를 분리한다. 제품에 필요한 backend+prototype을 함께 패키징하되 `.local/qa`·review 결과물·개발 인증정보·DB/media·브라우저 프로필은 배포물에서 제외한다. `current` 심볼릭 링크로 사용할 릴리스를 바꾸며 설정·DB·media·백업은 릴리스 밖에 둔다. 현재 backend가 사용하는 prototype 파일 관계를 유지한다.

릴리스 식별에는 Git SHA뿐 아니라 **누적 미커밋 소스 manifest 해시와 lock 해시**를 포함한다. 현재 같은 HEAD가 같은 소스 버전을 뜻하지 않는다. QA DB를 첫 운영 DB로 복제하는 정책은 정하지 않았다.

1. 변경할 수 없는 배포물·locked 설치를 준비하고 설정 검사와 static 수집을 확인한다.
2. 마이그레이션 계획·구 스키마 호환성·복구 가능한 백업을 확인한다. 필요한 쓰기 중단 시간과 데이터 손실 가능성을 사용자에게 확인한다.
3. 승인된 운영 작업에서 마이그레이션을 한 번 수행하고 코드 전환·서비스 재시작 후 공개/관리자·이미지 경계·TLS를 확인한다.
4. **스키마가 호환될 때만** 이전 코드로 전환한다. 비호환 변경은 전진 수정 또는 같은 시점의 DB+media 복구를 검토하며 데이터 손실을 먼저 확인한다.

위 순서는 제안이며 배포 스크립트·실행 명령은 아직 없다. 실제 서버·DNS·인증서·운영 배포는 별도 승인 범위다.

## 7. W004·W019 운영 판단 대기

**W004 — HSTS:** 현재 0이며 이번에 바꾸지 않는다. 실제 도메인의 HTTPS·인증서 자동 갱신·redirect·secure cookie·위조 프록시 헤더를 확인한 뒤 **300초 → 86,400초 → 장기값**으로 단계 적용하는 초안을 사용자에게 확인받는다. 초기 `includeSubDomains`·preload는 사용하지 않는 안이다. 브라우저에 남은 HSTS 때문에 장애 시 HTTP로 즉시 되돌릴 수 없다는 영향도 포함한다. [Django HSTS 설정](https://docs.djangoproject.com/en/5.2/ref/settings/#secure-hsts-seconds).

**W019 — SAMEORIGIN:** 현재 설정을 우선 유지하는 제안이다. [Post·BrandContent·Branch·Trainer](../backend/news/models.py)는 `PreviewableMixin`을 사용하고 설치된 Wagtail 7.4.3의 preview side panel iframe 및 `xframe_options_sameorigin_override`를 확인했다. 전역 DENY는 관리자 미리보기를 막을 수 있다. 같은 원점 iframe 허용 위험을 기록하고 실제 운영 원점의 미리보기·외부 원점 frame 차단·Nginx의 중복 X-Frame-Options/CSP 충돌을 검증한다. 필요하면 좁은 예외를 별도 설계한다. [Django clickjacking 방어](https://docs.djangoproject.com/en/5.2/ref/clickjacking/). 이번에 경고를 해결한 것으로 보고하지 않는다. 기존 W01 등 다른 관찰은 이번 범위 밖이다.

## 8. 선택과 다음 작은 단위

지금 설계가 사용자에게 확인할 핵심 선택은 **무료 용량 부족·유휴 회수·복구 지연 조건을 수용하고 A 준비를 진행할지**, 또는 **유료 예산을 정해 안정적 운영 구성을 다시 검토할지**다. A 준비를 선택해도 실제 서버 생성·배포까지 승인한 것으로 해석하지 않는다.

백업의 일별 7개·주별 4개, 일별 PC 사본, RPO 24시간·조건부 RTO 4~8시간 초안의 수용·조정은 인프라 선택 후 백업 구현 전에 확정할 수 있다. 도메인명·계정/DNS 권한은 DNS 준비 전에, 실제 콘텐츠·운영 권한·초기 데이터 반영은 공개 전에 확인한다. 이 미결정들이 문서 작성을 막지는 않는다.

선택 후 별도 지시할 다음 작은 단위는 **WSGI 진입점·호환 Gunicorn 고정·systemd/Nginx/환경 배치 템플릿과 격리 리허설**이다. 선택 전에는 시작하지 않는다. 실제 서버·DNS·인증서·배포는 다시 구분한다.

## 9. 이번 확인과 한계

이번에는 문서·관련 코드의 읽기 확인, 제공된 공식 한도 근거 대조, 문서 경로·링크·문구 일치만 검사했다. 외부 링크는 HTTPS 형식을 확인했으며 이번 문서 검사에서 모든 URL을 다시 요청한 것은 아니다. **제품/서버/QA 검사 재실행 0, 새 QA 자원 0**이며 기존 서버·환경에 접근하지 않았다.

OPS-01 개발 전체 164/164·독립 선택 16/16·후속 설정 8/HTTP 16은 [기존 기록](../backend/review/ops-01/README.md)에서 인계한 결과다. 이번 재실행이나 이전 142/148 등과의 합산이 아니다. 실제 OCI 계정·수용량·IPv4 견적, ARM 호환성, 운영 DB·TLS·프록시·배포·백업 복구는 미검증이다. 과거 QA JSON·캡처, 보류된 `/tmp` 잔여물과 기존 환경의 보존·정리 상태는 이번에 변경하지 않는다.

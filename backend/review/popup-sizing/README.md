# 복수 팝업 창 크기 수정 검수

**이력 안내:** 아래 검수는 탭당 한 번 정책 당시의 창 크기 수정 기록이다. 이후 일반 닫기 후 새로고침·홈 재방문마다 다시 노출하도록 사용자 확인을 받았다. 현재 직접 확인에는 새 탭이 필요하지 않으며 [최신 동작·크기 회귀](../popup-revisit/README.md)를 따른다. 이 폴더의 JSON·캡처는 당시 결과로 보존한다.

2026-10-10. 실제 CMS 홈의 PC 팝업 크기 수정 기록이다. 사용자 첨부 Whale 화면에서 한 창은 작고 나머지는 화면 폭까지 크게 열렸다. 과거 [팝업 연결 검수](../popups/README.md)는 headless에서 창 크기 변경을 확인하지 못했으므로 실제 크기의 완료 근거가 아니었다. 이번 자동 검사도 사용자 시각 승인과 구분한다.

## 원인과 수정

- 창 생성 직후 `outerWidth`를 그대로 목표 폭으로 재사용하고 한 번만 `resizeTo`를 호출했다. 이번 headed 재현에서는 네 창 모두 초기 `outerWidth=0`, `innerWidth=1440`을 거친 뒤 실제 창 폭 1440px로 남았다. [수정 전 경계·측정 이력](baseline.json).
- CMS 전용 `popup-sizing.js`로 본문 폭 480px·초기 높이 520px을 요청한다. 글꼴·사진 준비 뒤 실제 내용 높이를 측정하고 비동기 변경을 다시 확인한다. 브라우저 테두리 크기가 아직 유효하지 않으면 그 임시 값을 사용하지 않는다. 재시도는 최대 12회·4.5초로 제한해 이후 사용자의 수동 크기 변경을 방해하지 않는다.
- `popup-window.css`로 `100svh` 최소 높이·남는 높이를 채우는 flex·컨트롤의 자동 위 여백을 제거한다. 새 탭/크기 변경 제한에서도 내용 다음에 닫기가 배치된다. 긴 내용은 작업 영역 이하의 창 안에서 스크롤한다.
- 기존 색상·글자·텍스트형 ‘닫기 ×’·12px 하단 여백과 전체 자동 노출·등록 순서·오늘 숨김·모바일 순차 레이어를 유지한다. 데이터·관리자·노출 정책 변경은 없다. 원본 프로토타입 UI와 과거 캡처를 재생성하지 않았다.
- 크기 조절이 비동기이고 창 테두리를 포함한 값이라는 API 조건도 확인했다. [MDN resizeTo](https://developer.mozilla.org/en-US/docs/Web/API/Window/resizeTo).

Chromium을 **headless:false + viewport:null**로 실행하고 브라우저 자체의 `Browser.getWindowForTarget` 경계와 DOM·안쪽/바깥쪽 크기를 대조했다. 먼저 네 창 모두의 크기를 검사한 뒤 캡처했으므로 마지막 활성 창만 검사한 것이 아니다. 본문 사진은 로딩 뒤 캡처했고 이미지 표시 비율도 확인했다.

```bash
# backend/에서 실행. 기존 CMS·보존 자료 서버와 그래픽 세션 필요.
node scripts/review-popup-sizing.mjs
uv run python manage.py test news.tests --noinput --verbosity 2
uv run python manage.py check
uv run ruff check .
uv run ruff format --check .
```

- [크기·브라우저 검사 결과](checks.json), [실행 출력](browser-tests.txt): 실제 창 네 개 전체 크기 2회(8768 직접/8767 경유), 새로고침 중복 방지, 공개 글 이동·선택 지점, 한국 시간 오늘 숨김, 사진·글꼴 지연, 사진 실패, 초기 잘못된 크기, 사용자 수동 크기 변경, 긴 내용·440×600 작업 영역, 크기 변경 제한, 차단 후 수동 열기, 모바일 375×812/568 순차 레이어를 확인한다.
- [서버 회귀 출력](server-tests.txt): 기존 소식 CMS·공개본/초안·권한·기간·저장 충돌을 포함한 **33개 통과**. 별도 테스트 DB를 사용했다.
- `manage.py check`, `ruff check .`, `ruff format --check .`와 변경 JS의 `node --check` 통과. 기술 버전·의존성 변경 없음.
- 브라우저 스크립트는 기존 앱 DB를 읽기만 한다. 사진·긴 내용·실패·작업 영역 제한은 브라우저 응답/환경을 대체한 검수 자료이며 운영 데이터로 저장하지 않았다. 긴 제목·설명은 현재 필드 최대 200/300자 이내다.

## 직접 확인과 한계

기존 팝업을 닫고 **새 탭**에서 [실제 홈](http://localhost:8768/?branch=second)을 연다. 탭당 자동 묶음 한 번과 오늘 숨김 정책은 유지한다. 검토용 팝업 기간이 끝났으면 CMS에서 기간을 별도로 조절해야 하며 스크립트가 자동 연장하지 않는다. 기존 8767 홈도 실제 홈으로 이동한다.

- 첨부 Whale 화면은 확인했으나 Windows 직접 제어 도구는 `sandboxCwd is not a local file URI` 연결 오류로 실행하지 못했다. 초기화 후에도 같아 Whale 직접 검사는 미실행이다. Linux 그래픽 세션의 실제 Chromium 창 크기 검증으로 대체했으며 Whale 통과로 보고하지 않는다.
- 작은 작업 영역·크기 변경 불가·자동 차단은 의도적인 환경 대체다. 실제 작은 모니터/OS 배율, 브라우저 자체 차단 설정, Whale·다른 브라우저·실제 모바일 기기 검증으로 확대하지 않는다.
- 새 시각 결과의 사용자 재확인은 아직 없다. 백엔드·다른 마일스톤·프로토타입 원본 기능으로 범위를 확장하지 않았다.

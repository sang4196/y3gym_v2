# PC 팝업 중앙 랜덤 배치 검수

2026-10-10 사용자 요청: PC 팝업을 같은 위치에 쌓아 시작하지 않고 중앙 주변에 랜덤하게 배치하며 화면 가장자리에 붙지 않도록 한다. 모바일·관리자·DB·노출 개수와 등록 순서는 변경하지 않았다. 기존 정적 프로토타입과 과거 검수 자료는 보존했다. 이 기록은 사용자 시각 승인을 대신하지 않는다.

## 변경

- [창 크기·위치 계산](../../news/static/news/popup-sizing.js): 기본 가장자리 여백 48px. 중앙 분산은 가로 최대 ±180px·세로 최대 ±100px이며 화면 크기와 남는 공간에 따라 축소한다. 중앙 3×3 구역을 섞고 각 구역 안에 무작위 편차를 더한다. 첫 9개는 구역을 중복 선택하지 않으며 이후 다시 섞는다. 일부 겹침은 가능하다.
- [홈 실행기](../../news/static/news/home-popups.js): 모니터 작업 영역의 원점을 반영한 `left/top`을 처음부터 지정한다. 동일 출처·실제 창·글 ID를 검증해 자식 창에 같은 랜덤 기준점을 전달한다. 수동 클릭의 동기적 `window.open`과 글별 이름 재사용을 유지한다.
- [별도 창 실행기](../../news/static/news/popup-window.js): 글꼴·사진 로딩 후 내용 크기와 위치를 보정하고 준비 완료를 알린다. 운영체제의 창 테두리로 생기는 작은 좌표 차이도 실제 이동 결과로 보정한다. 초기 보정은 최대 12회·4.5초 이내이며 이후 사용자의 이동·크기 변경을 지속적으로 되돌리지 않는다.
- 브라우저가 요청과 다른 모니터에 창을 열면 실제 열린 화면의 작업 영역을 사용한다. 창 크기는 여백을 뺀 영역 이하로 제한하고 긴 내용은 스크롤한다. 매우 작은 화면은 최소 창 공간을 위해 여백을 줄인다.

## 실제 검수

현재 공개된 TEST 글 17·18·21·22를 읽었다. 새 글 작성이나 DB 설정 변경은 없으며 오늘 숨김은 검수용 브라우저 컨텍스트에만 저장했다.

위치 검수는 **화면이 표시되는 Chromium + `viewport:null`**을 사용했다. `Browser.getWindowForTarget`의 실제 창 경계와 JS의 좌표·크기를 대조했다. 시작 좌표 요청과 최종 실제 좌표는 [JSON](checks.json)의 `opens`·`windows`로 구분한다. 캡처는 실제 팝업의 본문이며 전체 데스크톱이나 창 장식의 스크린샷은 아니다.

최종 첫 묶음의 실제 작업 영역은 1920×1080, 원점 (0, 0)이었다. 요청 시 홈의 작업 영역 원점은 (1920, 0)이었으나 이 환경에서는 팝업을 다른 화면에 생성했다. 최종 좌표는 실제 열린 화면의 중앙을 기준으로 보정했다.

위치 JSON에는 정상·재노출·사진·고정 난수·수동 열기의 **실제 창 17개**를 기록했다. 이동 제한 검사는 별도 4개 창에서 수행했다. 음수 모니터 원점과 작은 화면 좌표는 합성 입력에 대한 계산 검사이며 실제 기기/모니터 검증과 구분한다. 이번 JSON의 페이지 스크립트 오류는 0건이다.

초기 실패 이력은 `attempt-1`~`attempt-9`의 JSON·출력에 보존했다. 창 생성 중 일시적인 좌표, 운영체제 테두리 오차, 모니터 작업 영역 차이를 확인했고 코드를 보완했다. 검수에서도 지난 페이지의 세션 기록을 완료 신호로 사용하지 않고 현재 페이지의 새 준비 메시지를 기다리며, 사용자 이동 후에는 요청 좌표 대신 실제 적용된 경계가 유지되는지 비교한다. 크기 회귀의 초기 두 실패도 `sizing/attempt-1`·`attempt-2`에 보존했다. 마지막 재실행은 실제 창 25개의 크기를 기록했다. 브라우저 창 생성 이벤트의 도착 순서와 자동 열기 호출 순서를 구분해 등록 순서는 실제 `window.open` 호출로 검사한다.

변경한 JS·검수 스크립트 6개에 `node --check`를 실행해 통과했고, 현재 문서의 상대 파일 경로도 [검사 결과](document-checks.json)에 기록했다. 서버/CMS 테스트의 과거 통과 기록과 이번 브라우저 검증은 구분한다.

## 재현

백엔드와 보존 자료 서버의 실행법은 [백엔드 README](../../README.md)를 따른다. 기간 내 공개 팝업 예시가 두 개 이상 필요하다. 아래 명령은 DB를 읽기만 하며 지정한 이번 검수 폴더의 결과를 갱신한다. 위치·크기 검수에는 그래픽 세션이 필요하다.

```bash
cd backend
node scripts/review-popup-position.mjs
Y3GYM_POPUP_REVIEW_DIR=review/popup-position/sizing node scripts/review-popup-sizing.mjs
Y3GYM_POPUP_REVIEW_DIR=review/popup-position/revisit node scripts/review-popup-revisit.mjs
Y3GYM_POPUP_REVIEW_DIR=review/popup-position/edges node scripts/review-popup-edges.mjs
```

[실제 홈](http://localhost:8768/?branch=second)을 새로고침해 확인한다. 일반 닫기는 다시 표시하고 오늘 숨김을 선택한 글만 한국 시간 다음 날 0시까지 숨긴다. 브라우저가 자동 열기를 차단하면 해당 글의 ‘직접 열기’ 링크를 사용한다.

## 제한

- 이번 직접 검사는 Linux Chromium이다. Windows Whale·실제 모바일·운영 배포 환경과 실제 다중 모니터 조합 전체는 미검증이다. 사용자 시각 재확인 전이다.
- 브라우저가 창을 새 탭으로 바꾸거나 이동을 제한하면 사이트에서 실제 좌표를 강제할 수 없다. 요청 좌표와 제한된 재시도 후에도 읽기·닫기를 유지한다. 관련 API 조건은 [MDN window.open](https://developer.mozilla.org/en-US/docs/Web/API/Window/open)·[moveTo](https://developer.mozilla.org/en-US/docs/Web/API/Window/moveTo)를 확인했다.
- 서버·관리자·DB 로직은 변경하지 않았다. 이번 작업에서 Python 서버/CMS 전체 테스트를 다시 실행한 것으로 보고하지 않는다. 이전 결과는 [게시글 연결](../popups/README.md)·[크기 수정](../popup-sizing/README.md)·[재노출 수정](../popup-revisit/README.md)의 당시 기록이다.

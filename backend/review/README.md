# M1 소식 CMS 검수 기록

검수일: **2026-10-10 한국 시간**. 기존 정적 프로토타입 보고서를 읽은 것과 이번 실제 서버·브라우저 실행을 구분한다. 이번 검수는 새 `backend/`·별도 로컬 PostgreSQL에서 수행했으며 운영 배포나 사용자 디자인/편집 경험 승인은 아니다.

## 이번에 실제 실행한 검사

아래 명령은 `backend/`에서 실행했다.

| 명령 | 결과 |
| --- | --- |
| `uv sync --locked` | 고정 의존성 설치 완료. 최초 잠금 파일 생성은 `uv lock` 후 수행 |
| `docker compose --env-file .env.local up -d --wait` | M1 전용 DB 실행·healthy. 기존 55437 DB는 변경하지 않음 |
| `uv run python manage.py migrate` | Wagtail 및 소식·이미지 초기 마이그레이션 적용 |
| `uv run python manage.py bootstrap_review` | 로컬 계정·두 테스트 소식 준비. 기존 데이터·비밀번호 초기화 없음 |
| `uv run python manage.py check` | 문제 없음 |
| `uv run python manage.py makemigrations --check --dry-run` | 누락 변경 없음 |
| `uv run ruff check .` | 통과 |
| `uv run ruff format --check .` | Python 파일 20개 확인·통과 |
| `uv run python manage.py test news.tests --noinput --verbosity 2` | **17개 통과**, 실제 PostgreSQL 테스트 DB 사용·종료 후 제거. [출력 기록](server-tests.txt) |
| `node scripts/review-cms.mjs` | **8개 흐름 통과, `PASS_WITH_WARNINGS`**. [실제 결과](checks.json) |

서버 검사는 초안 비노출, 관리자 일반 URL도 공개본만 제공, 공개 중 수정 초안의 제목·본문·분류·날짜·사진 보존, 재공개·철회, 공유 이미지의 마지막 사용처, 원본/초안/썸네일 권한, 파일 덮어쓰기 차단, 미리보기 권한, 본문 정제, CSRF·무권한 변경, 오래된 화면의 충돌, **두 HTTP 저장 요청의 실제 동시 실행**, 초기 데이터 명령의 재실행 보존을 확인했다.

브라우저는 headless Chromium에서 실제 운영자 로그인과 폼을 사용했다. 한글 텍스트·문단·Shift+Enter 줄바꿈·굵게, 대표/본문 이미지 업로드·삽입·교체, 초안 저장·미리보기, 명시적 공개, 수정 초안 중 기존 공개본 유지, 재공개, **CMS 확인 폼을 통한 공개 철회**, 이미지 HTTP 상태·`no-store`, JS 비활성 모바일 탐색을 확인했다. 목록·상세는 **320·375·768·1024·1280·1440px**에서 글꼴·이미지 로딩·사진 원본 비율·가로 넘침을 확인했다.

별도의 Playwright 단발 검사로 375×812에서 모바일 메뉴 열기·닫기, 예시점 문의 링크, 스크롤 최하단의 푸터 설명이 고정 문의 바에 가리지 않는 것을 확인했다. 실제 결과와 좌표는 [navigation.json](navigation.json)에 있다. 이 보조 검사는 `review-cms.mjs`의 8개에 합산하지 않았다.

## 발견·수정한 문제와 남은 문제

- 목록 제목의 상세 변수 참조, 본문 이미지·줄바꿈 태그의 편집기 저장 형식을 수정했다. 줄바꿈과 본문 이미지를 저장 후 다시 여는 서버 회귀 검사를 추가했다.
- Draftail의 숨은 필드 반영 지연으로 입력 직후 저장에서 마지막 문장이 누락되는 문제를 발견했다. 실제 제출 전에 편집 상태를 반영하는 JS를 추가하고 같은 브라우저 흐름을 통과했다.
- CMS 이미지의 고정 높이 속성 때문에 모바일에서 늘어나던 사진을 `height: auto`로 보정했다. 기존 프로토타입 CSS·레이아웃·색상·글꼴은 변경하지 않았다.
- **남은 문제:** Wagtail 7.4.3의 중복 이미지 업로드 확인에서 탭 패널 불일치 브라우저 오류가 8회 관측됐다. 새 이미지 사용·본문 삽입·교체·공개 흐름은 끝까지 통과했지만, 콘솔 오류 없음으로 보고하지 않는다. 원문·발생 URL은 JSON의 `warnings`에 남기며 그 외 예상하지 않은 JS 오류는 0건이었다. 동일 메시지만 별도로 분류했고 다른 오류는 검수를 실패시킨다. 이 기본 관리자 문제의 해결은 미완료다.

검수 개발 중 실패한 실행도 있었다. 이번 작업에서 만든 테스트 글만 수정·철회했고 글·이미지 원본은 삭제하지 않았다. 실패 실행의 테스트 초안이 관리자 목록에 남아 있으며 모두 테스트 제목으로 표시된다. 최종 결과는 위 JSON과 서버 출력이다. 새 스크립트 재실행 시 이 폴더의 같은 이름 결과·캡처를 갱신한다.

## 보존 확인과 미검증

작업 시작 시 `prototype/`와 `docs/legacy/`의 기준 파일 189개를 SHA-256으로 기록했다. 끝에 비교하여 **`prototype/README.md`, `prototype/DESIGN.md`의 상태 문서 갱신만 있고 나머지 187개는 동일**, 누락은 없음을 확인했다. [보존 검사 결과](preservation.json). 프로토타입 HTML·CSS·JS·이미지·기존 검수 JSON·캡처·영상과 legacy는 재생성하거나 덮어쓰지 않았다.

현재 작업 문서 8개의 로컬 링크 145개가 실제 경로로 연결되는지 확인했다. `git diff --check`도 통과했다. 비밀값 파일의 0600 권한·Git 제외와 잠금 파일 URL에 인증정보가 없는 것을 확인했으며 비밀값 자체는 보고서에 기록하지 않았다.

미검증·미구현은 다음과 같다.

- 관리자 사용성·사진 입력 경험의 사용자 확인, 실제 기기·Chromium 이외 브라우저, 한국어 IME 조합 입력. 이번 한글 검수는 브라우저 텍스트 입력 자동화다.
- 브랜드·지점·시설·트레이너·팝업 CMS와 홈/팝업의 서버 데이터 연결. 본점·예시점은 계속 정적 예시다.
- 실제 자료·지도·전화·카카오톡, 최종 운영 권한·삭제/복원·공개일/정렬 정책.
- 운영 배포·HTTPS·외부 저장소·CDN·운영 캐시·부하·백업/복구. `no-store`는 현재 앱 경로에서만 확인했다.

M1 이후에는 관리자 편집 흐름을 사용자에게 확인받고 다음 브랜드·지점/시설 단위를 구체화한다. 이번 작업에서 그 기능을 시작하지 않는다.
